### 本 Phase 验收结论

## Phase 2：全局 authority 与状态机

- 已有 authority frontier、proof、issuance lease 和 CAS 的基础代码/迁移资产。


## Phase 3：持久化发布证明和 MemoryProjectionHub

**总体状态：`PARTIAL`。**

### 计划要求

- 只允许 `CertifiedAuthorizationState` 作为 MemoryProjectionHub 的可服务状态。
- `verify_and_install()` 必须验证完整内容、manifest/segment、signature、parent、term、fence、generation、revoke 和 durable publication proof。

- gap、rollback、UNKNOWN、同代冲突、writer active 和 key 分歧必须 sticky quarantine。
- DB restore 只能作为 cold hint，必须重新向 authority 对牌后才能 SERVING。

### 已完整或已有证据

本轮已闭合一个**本地合同子集**，不等于完整的分布式生产闭环：

- `MemoryProjectionHub` 记录单调递增的 `durable_reconcile_epoch` 和对应 mutation revision。
- source mutation、warm-up、suspect 和 authority recovery 会失效旧的 durable/ready evidence，避免沿用过期 `SERVING` 证明。
- `reconcile_from_durable()` 只记录本轮 durable evidence，不直接打开 `SERVING`。
- `mark_authority_reconcile_ready()` 要求同一轮 durable evidence、certified root、authority frontier、fresh channel health、无 active writer/unknown source/runtime-owner failure，且无阻断正向授权的 pending/revoke/gap/conflict。
- `complete_authority_fence_sync()` 只能消费同一 reconciliation epoch 的 ready evidence；没有或过期 evidence 时保持 fail-closed。
- `MemoryMirroredRuleRepository::certify_authorization_evidence()` 只安装 certified scope root，不再由请求路径直接推进 `SERVING`。
- LocalBus supervisor 在 authority readiness 未证明时继续 `Reconcile`，只有 `positive_authorization_ready()` 为真时才可 `Observe`。
- single-node 进程/worker/transport liveness 与 positive authority readiness 分离；liveness 不被当作授权证明。
- Hub fence-sync、authority pending recovery、supervisor 分支和 single-node 均有 Rust 合同测试。

这些证据只证明本地状态机的负向门和监督时序，不能证明 external arbiter/quorum、全 scope startup attestation 或真实跨节点全局 proof。

### 部分完成

- immutable Arc、root swap、generation、manifest/segment、revoke 和 pending 等局部证据仍已存在，但尚未由完整 certificate、external provider 和 durable publication proof 统一约束为唯一生产可服务类型。
- 本地 `FENCE_SYNCING -> SERVING` 现在有明确的 durable reconcile/ready epoch 门，但组合根尚未完成全 scope 的启动期 authority attestation；single-node 仍只能独立报告进程 liveness，不能据此报告 positive authority readiness。
- provider-backed proof、durable publication/current pointer、external authority frontier、跨节点一致性和 sticky quarantine 尚未形成完整生产调用链。

### 未完成

- `CertifiedAuthorizationState` 尚未成为唯一生产可服务类型。
- `verify_and_install()` 的完整 production contract。
- signature/certificate、current authority fence 和 durable publication commit proof 的联合安装门。
- 完整 manifest/current pointer/certificate/parent chain 的不可回滚证明。
- 同一 scope 同一 generation 的 hash、seal、parent、signature 或 key 分歧的 sticky quarantine。
- generation、term、global fence、revoke watermark 的全量单调 CAS。
- gap、rollback、UNKNOWN、writer active 时禁止继续正向授权的全链路门控。
- projector 只能安装已证明 durable publication 的约束。
- eviction、TTL、capacity、failed assembly、MQ invalidation 统一进入 authority 状态机。
- DB restore 作为 cold hint、重新对牌、验证证书链和未决 operation 后才恢复 SERVING。
- authority frontier 推进后旧 scope root 清理和回收证明。

### 本 Phase 验收结论

本地内存状态基础已经有价值，但不能据此称为认证内存权威。Phase 3 为 `PARTIAL`。
