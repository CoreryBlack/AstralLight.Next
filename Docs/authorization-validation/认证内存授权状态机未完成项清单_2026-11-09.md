本清单只记录当前 V7 目标中尚未形成完整生产闭环的事项。`PASS` 只表示对应的本地代码合同或 focused Rust 证据已成立，不表示真实 MySQL、RabbitMQ、etcd/quorum、部署或多节点验收通过。

状态含义遵循 `AGENTS.md`：

- `OPEN`：生产代码或生产组合仍缺少必要实现；
- `PARTIAL`：已有局部实现，但调用链、数据链或 readiness 尚未闭合；
- `BLOCKED`：需要外部环境、批准或部署前置，当前未启动；
- `PENDING`：已有路径主动保持安全等待，尚不能进入正向授权；
- `NOT PROVEN`：实现可能存在，但尚无足够证据证明目标性质。

## 2. P0：生产代码闭环

### 2.1 六类事实族的完整 durable materialization

状态：`OPEN/PARTIAL`

需要把以下六类事实从各自 source owner 接入统一的 durable-to-certified completion 链。六个 ledger-backed adapter、严格 completion reader 和 schema contract 已实现，但它们只消费 source-owner completion rows；source owner 的写入、authority-bound completion 和完整生产 materialization 仍为未完成项：

- [x] 已有六个显式 ledger-backed family adapter、严格 completion reader 和 additive schema contract；adapter 只消费 source-owner completion rows，不从空查询推导 `CompleteEmpty`，不替代 source completion 或 authority proof。
- [ ] card context / eligibility source owner 写入 completion ledger；
- [ ] GlobalAdmin source owner 写入 completion ledger；
- [ ] published evidence source owner 写入完整 manifest/segment/pointer/history completion；
- [ ] ORG authorization source owner 写入 membership/edge generation、revoke、publication 与 provenance completion；
- [ ] ownership source owner 写入完整 memory-eligible route inventory completion；
- [ ] SoD policy source owner 写入 dynamic-owner、ORG contribution/provenance 和 policy digest completion；

每个事实族都必须能提供并核验：

- [ ] source commit identity 和 source outcome digest；
- [ ] before/after 或完整内容 digest；
- [ ] 稳定 `operationId`、`eventId` 和必要的 `messageId`；
- [ ] audit correlation；ledger writer 已拒绝超过 64 字节或缺少 `detail.operationId`/`auditCorrelationId` 绑定的写入，但生产审计尚未统一写入后者，独立关联身份未闭合；
- [ ] scope generation、revoke watermark 和依赖代际；
- [ ] 有界且完整的 inventory；writer 已拒绝与 payload 逐项不一致的调用方形状，但不证明六族 source inventory 完整；
- [ ] UNKNOWN 结果的对账状态；
- [ ] family certificate 或等价的 authority-bound completion 证据。

当前 snapshot builder 在无法证明上述完整覆盖时返回 `Pending/Unavailable`，不会把局部 published evidence 读数标为完整 Serving。这是当前正确的 fail-closed 行为，但不是完成证明。

8. 在受保护环境中执行 MySQL、RabbitMQ、etcd/quorum、多节点、S15/TLC 和 delivery 验收。

任何一步出现 UNKNOWN、gap、stale、同代 divergence、root/snapshot mismatch 或无法证明 durable postcondition，都必须保持 `PENDING/DENY`，不得跳过对牌或使用旧快照恢复 `ALLOW`。

## 7. 完成判定

本清单全部关闭的必要条件是：

- 六类事实族均有完整 durable materialization 和 authority-bound completion；
- authority root 与本地 immutable snapshot 完全匹配并安装 attestation；
- F0/F1 每次请求 proof identity 和 request binding 均可验证；
- ownership、SoD、ORG provenance 和 policy evidence 使用一致 read token；
- single-node CertifiedMemory 能完成 preflight 并进入 `Serving`；
- 失效、回滚、分区、UNKNOWN、worker restart 和 token drift 均可恢复且不放行 stale `ALLOW`；
- 真实 MySQL、RabbitMQ、etcd/quorum、mTLS、多节点、migration、deployment 和 S15/TLC 取得各自 durable postcondition；
- 通过人工终审，且没有把 ignored、ACK、HTTP 成功或本地缓存命中当作授权证明。

在上述条件全部满足前，项目整体不得标记为 `COMPLETE` 或生产 `READY`。
