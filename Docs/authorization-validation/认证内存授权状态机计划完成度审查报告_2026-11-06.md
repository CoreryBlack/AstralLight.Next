### 2.2 独立 authority 与历史证据

`astral-authority` 已使用 etcd client adapter，具备线性化读取、CAS transaction、lease-backed leadership 与 mutation 内 leader-token fence。全局 frontier、canonical scope certificate 和请求 fresh proof 分开；普通读取不推进 publication fence。签名、key/epoch/term、历史 frontier、证书 history/current 和 exact replay 已有生产代码及本地合同。

业务 MySQL authority 数据作为本地投影和事务证据，不独立发号。canonical Card 内容身份与请求的 user/domain lens 分离。历史 receipt 必须验证 retained 内容和签名链；旧 quorum snapshot 本身不能证明防回滚。真实三成员 quorum、独立故障域、分区、恢复与密钥部署仍未验收。

### 2.3 F0/F1、认证内存与宿主装配

Provider 已接每次 nonce 的实际 fresh proof 获取，F0/F1 独立 identity，并检查 frontier、scope/dependency 与 publication identity。认证内容安装、Hub reconcile epoch、readiness 和 liveness 分离；缺 proof、缺依赖、过期或漂移时保持 `PENDING/DENY`。正式授权仍经 `PolicyEngine::evaluate()` 及 published-evidence strict gate。

Identity、TrustGraph、Monitor 已接严格宿主链。组合宿主加载一次配置，启动 DB/worker 前校验角色配置；TrustGraph 作为唯一网络 receiver/journal owner，Identity 保持 source producer 职责。缓存命中、存活状态和冷数据库内容不单独打开正向服务门。真实启动、authority 断联/恢复和完整冷恢复仍需外部验收。

### 2.4 Source 提交、独立完成与 UNKNOWN

敏感 source 使用 exact reservation，同事务 durable admission-use、source/evidence 与 audit correlation，并在已证明 COMMIT 后交完整 receipt。请求只观察 exact completion，WorkerOwned 负责发布；网络、缓存/MQ、compile、retry、install 与等待不进入 source transaction。

`ProtectedBusiness` 的 `COMMITTED` 保持终态，无授权 publication barrier；`AuthorizationSource` 的 `COMMITTED` 为中间态，后续需正式发布或已登记的独立完成。ELIGIBILITY/CONFIG 各自核验真实 typed source，不伪造 delta/certificate/current 来关闭 reservation。

UNKNOWN 必须按稳定身份对账，不重放 source、不以 lease 过期或 HTTP 状态作为 rollback/abort 证明。durable abort 与实际消费/提交互斥。审查曾推断“admission 消费后 exact Completed replay 不可达”，该推断已撤回：validate 不查询 durable-use，仍有效且精确绑定的 proof 可以读回 Completed；过期或撤销后保持 `PENDING`。

### 2.5 CardCreate、资格 fanout 与 CardRebind
