## 2. 按批准计划核对完成项

### 2.1 协议、edition 与迁移合同

V7 已登记独立 authority、global frontier、逐 scope certificate、每次 fresh proof、敏感 source admission、独立完成与恢复合同；V6 保留历史边界。工程规范入口为 [Rust 规范 §15.9](../规范/Rust后端编码规范_V1.0.md#159-v7-authority-生产协议与采用合同2026-11-07)，消息合同见[统一消息规范](../规范/统一消息协议与智能层消息规范_2026-03-18.md)。

Additive migration 源码、注册、exact artifact/hash、preflight 与 runtime schema 合同已纳入本地编译和测试。**源码合同通过不代表真实 DDL、数据采用、备份恢复或部署完成。** 历史 migration/hash 没有因新的协议语义而被解释为已执行。

### 2.2 独立 authority 与历史证据

`astral-authority` 已使用 etcd client adapter，具备线性化读取、CAS transaction、lease-backed leadership 与 mutation 内 leader-token fence。全局 frontier、canonical scope certificate 和请求 fresh proof 分开；普通读取不推进 publication fence。签名、key/epoch/term、历史 frontier、证书 history/current 和 exact replay 已有生产代码及本地合同。

业务 MySQL authority 数据作为本地投影和事务证据，不独立发号。canonical Card 内容身份与请求的 user/domain lens 分离。历史 receipt 必须验证 retained 内容和签名链；旧 quorum snapshot 本身不能证明防回滚。真实三成员 quorum、独立故障域、分区、恢复与密钥部署仍未验收。

### 2.3 F0/F1、认证内存与宿主装配

Provider 已接每次 nonce 的实际 fresh proof 获取，F0/F1 独立 identity，并检查 frontier、scope/dependency 与 publication identity。认证内容安装、Hub reconcile epoch、readiness 和 liveness 分离；缺 proof、缺依赖、过期或漂移时保持 `PENDING/DENY`。正式授权仍经 `PolicyEngine::evaluate()` 及 published-evidence strict gate。

Identity、TrustGraph、Monitor 已接严格宿主链。组合宿主加载一次配置，启动 DB/worker 前校验角色配置；TrustGraph 作为唯一网络 receiver/journal owner，Identity 保持 source producer 职责。缓存命中、存活状态和冷数据库内容不单独打开正向服务门。真实启动、authority 断联/恢复和完整冷恢复仍需外部验收。

### 2.4 Source 提交、独立完成与 UNKNOWN

敏感 source 使用 exact reservation，同事务 durable admission-use、source/evidence 与 audit correlation，并在已证明 COMMIT 后交完整 receipt。请求只观察 exact completion，WorkerOwned 负责发布；网络、缓存/MQ、compile、retry、install 与等待不进入 source transaction。

`ProtectedBusiness` 的 `COMMITTED` 保持终态，无授权 publication barrier；`AuthorizationSource` 的 `COMMITTED` 为中间态，后续需正式发布或已登记的独立完成。ELIGIBILITY/CONFIG 各自核验真实 typed source，不伪造 delta/certificate/current 来关闭 reservation。

UNKNOWN 必须按稳定身份对账，不重放 source、不以 lease 过期或 HTTP 状态作为 rollback/abort 证明。durable abort 与实际消费/提交互斥。审查曾推断“admission 消费后 exact Completed replay 不可达”，该推断已撤回：validate 不查询 durable-use，仍有效且精确绑定的 proof 可以读回 Completed；过期或撤销后保持 `PENDING`。

### 2.5 CardCreate、资格 fanout 与 CardRebind

CardCreate 已核完整 enabled ALLOW 贡献、GrantDelta/provenance、BASE refs、真实审计、CARD parent 和新 INSERT first-publication origin。空 RuleSet 保留 receipt；CARD 与 RuleSet generation 分开；parent actor/operation 与实际 BIND_CARD 和原创建 operation 精确绑定。

资格采集要求完整、有界 Card 集合和每卡 generation/revoke/outbox/message；超界拒绝整个 mutation。零集合仅接受登记的 typed fanout 证明。CARD refresh/correlation 与 ELIGIBILITY invalidation 分别记录、失效和验证。

相同模板重绑显式 rollback，不制造 source evidence；不同模板且有真实贡献时进入 delta publication。零贡献重绑通过专用 `CardRebindCapture` 和独立 ELIGIBILITY 完成，核完整卡与模板镜像、old/new BASE refs（含实际 ID/created_at）、RuleSet aggregate union、当前锁定 grant history、CARD_UPDATE parent、完整审计及精确 receipt。worker 独立读回并验证，不仅相信 producer 自报。专用负例及相关资格合同已实际运行，真实 MySQL 路径仍未执行。

### 2.6 外围 writer、verification 与 delivery

审批 create/cancel/reject 使用精确登记的 ProtectedBusiness 分类，approve/revoke 保留授权 source；commerce 保持业务语义并增加 admission、幂等、实际 before/after 和审计。Monitor/replay/stats、其他配置 writer 及直接调用方已在本地实施和主审范围内纳入统一门。

Verification 已有共享有界 limiter、durable budget/尝试计数、摘要验证、用途/目标绑定及单次消费合同。EMAIL/HTTPS delivery adapter、durable intent 和稳定 message identity 已接生产路径；缺配置或不能证明交付时明确 unavailable/`PENDING`。密码重置消费要求 durable `DELIVERED` 与 token/message/operation 精确绑定。Provider 接受不等于最终送达，UNKNOWN 不能自动重发；真实邮件、短信和通知未发送。

### 2.7 消息、关闭所有权与 S15 工具边界

同库自研 mTLS、跨库 recipient-targeted RabbitMQ、durable journal/inbox/outbox 和观察接口已接线。观察接口核完整 staged set 与字段，未知状态或缺少证据返回 UNKNOWN。broker confirm、ACK、本地任务结束和远端 `APPLIED` 分开。

取消和超时后，registry 保留 owner `JoinHandle` 与 mTLS `JoinSet`，直到独立 reaping 证明结束；所有 owner 先收到关闭信号，共用 deadline，failure sticky。调用方超时返回 UNKNOWN，继续本地回收，不据此重放发送或宣称远程完成。宿主按依赖顺序关闭，失败继续收集，authority outcome runtime 最后关闭。

Rust S15 parser、production observation adapter、probe/coordinator 合同已纳入验证；声明 prerequisites 与探针成功不能证明完整 campaign。真实 fault controller、四服务器两半区部署、故障注入和 durable postcondition 仍未完成验收，不能把已有工具或局部 HTTP/TLS 探针称为 S15 `PASS`。
