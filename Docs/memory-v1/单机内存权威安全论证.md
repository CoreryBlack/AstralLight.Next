# memory-v1 单机内存权威的安全论证

> 2026-11-18，第一版。本文给出普通受保护请求的正向准入定理、A/A1 目标协议的前缀不变式、Rust 有界枚举和实现映射。源码映射针对 `DarkStar` 上以 `4ab9f7d` 为基点的当时工作树，包含未提交的规则索引和日志协调器修改。工程合同见 [Rust 规范 §15.10](../规范/Rust后端编码规范_V1.0.md#1510-memory-v1-单机内存权威合同2026-11-12)。

## 1. 模型与假设

令 `X(t)` 是请求期间某一实际时刻的权威状态，包含唯一服务根实例、已发布授权事实及索引、会话权威、注册表和写栅栏。令 `q` 是入口验证并绑定的请求。`Permit(X,q,T)` 是顺序规范中的准入谓词，按系统可信时钟的采样值 `T`，检查会话、双卡、租户、绑定、确认、规则、适用资源事实和约束，要求无有效拒绝且无未决依赖。一次成功准入使用一个时间点上的一致状态解释。

| 假设 | 要求 |
|---|---|
| A1 · 来源与唯一性 | 请求身份、对象与动作绑定有可信来源。进程中只有一个服务根和匹配的会话权威。发布初始事实完整且通过验证。 |
| A2 · 完整依赖 | 针对 `q`，投影 `πq(X)` 充分决定 `Permit` 的非时间输入。依赖集合包含可能改变结果的缺失事实、未命中分支与未来可能生效的规则。新增绑定使集合版本改变，索引与其底层事实等价。 |
| A3 · 发布与标识 | 更新在一个受控发布点呈现完整关系与索引。相同实例内，每个相关依赖的验证标识相等蕴含其语义值相等，标识耗尽时停止正向准入。若以摘要代替完整值比较，另需其编码和抗碰撞假设。 |
| A4 · 最终复核 | 复核在共享的同步边界内验证会话、根和注册表。栅栏观测覆盖采样点并检测相关开启，证据不足时拒绝准入。时钟样本可信，规则的时间窗口和完整的结果变化边界得到复核。 |
| A5 · 本地持久化 | 单写者与连续帧顺序成立。刷写成功覆盖已确认的前缀，恢复能识别有效且连续的前缀。A1 故障模型以本机存储完整及设备正确履行刷写为条件。 |
| A6 · 数据库基线 | 恢复依据一个可验证的基线和事务性应用进度。事实、独立审计行、回执和进度随同一次 DB 事务前进。发生不一致、未知结果或无法证明历史完整时，恢复不开放服务。 |

这里的时间变量 `t` 用于叙述并发历史，`T` 是应用评估的时钟值。线性化点可以选在真正读取 `T` 的时刻，即使时钟分辨率不足以区分两个事件。A4 仍要求时钟可信。源码只检测可见的回拨与时间边界，时钟服务属性需单独论证。

## 2. 定理一 · 普通 ALLOW 的点时安全

若普通请求 `q` 获得 `ALLOW`，在该请求调用和准入返回之间，存在时刻 `ℓ`，使 `Permit(X(ℓ), q, Tℓ)` 成立。取 `ℓ` 为最终复核中的时钟采样点。

**证明。** 初评在一个不可变读阶段上得到候选允许以及依赖和有效时间区间。最终复核通过时，由 A1 和 A3，读取阶段与当前权威属于同一有效实例，且相关依赖的标识匹配。由 A2，这意味着 `πq(X(ℓ))` 与初评使用的非时间事实在语义上相等。A4 保证会话在同一切点有效且栅栏允许准入，采样处于初评结果可保持的时间区间。若后续可能激活一条会改变结果的规则，区间不得跨过该激活边界。于是顺序准入谓词在 `ℓ` 为真。对 `πq` 之外的变更，整个根的版本可以前进，定理仍成立。∎

这一结论覆盖普通请求的正向准入。系统可以保守地返回 `PENDING`，例如同步边界争用、未装载事实或证据耗尽。批量、治理复合评估、业务响应的后续副作用和全部结果的线性化需要各自的精化证明。已准入请求的后续执行遵循请求生命周期合同。

**源码映射。** 普通引擎路径在候选允许后才构造复核记录，以最终采样时间签发准入。当前实现以非阻塞读守卫固定会话、根发布和注册表，再用两次不可变栅栏表观测包住采样。根复核独立枚举适用绑定，并检查实例、服务状态、卡和规则集代际、版本与存储摘要。允许的版本前进仍须保持请求依赖。预编译规则索引与绑定索引的完整性、全部写入口对代际的维护及可信对象归属都属于 A1–A3 的实现证明义务。当前论证对租户拓扑取固定前提，可变拓扑需要额外验证拓扑与代际同次发布。 [普通引擎入口](../../policy-engine/src/memory_v1_formal.rs#L1924) · [最终时钟](../../astral-authorization-root/src/memory_v1_session.rs#L490) · [根复核](../../astral-authorization-root/src/memory_v1_root.rs#L2167) · [栅栏观测](../../astral-authorization-root/src/memory_v1_fence.rs#L588)

## 3. 定理二 · A/A1 目标协议的响应与恢复

令 `L` 是目标协议中已原子登记的记录序列，每条消息有独立的日志位置 `i`。令 `M(k)` 是前 `k` 条记录中治理变更的条数。`R(k) = fold(R₀, L[1..k])`，其中治理记录按确定性的状态转换应用，DENY 记录对授权状态为恒等变换。已发布状态与该序列的前缀对应。令 `w`、`d`、`b` 分别表示连续写入、确认持久、DB 已提交的日志前缀长度。

```text
0 ≤ b ≤ d ≤ w ≤ |L|
DBFacts = R(b)
MutationSuccess(i) ⇒ i ≤ d ∧ 已发布对应变更
Forbidden(i, h) ⇒ Member(i, DENY, q, h) ∧ h ≤ d ∧ i ≤ d
```

`h` 是 DENY 的真实授权观测对应的历史前缀。`Member` 绑定操作标识、请求指纹、DENY 原因、观测实例与摘要。`h` 经独立的观测到前缀映射取得，可以为零。日志位置、变更序号、根实例内版本是不同标识。DENY 的追加位置或尾哈希无法独立建立这个映射。DENY 先阻止业务执行，只有两个证明齐备时才返回 403，证明不足时返回 503。

**归纳证明。** 空序列满足前缀关系和基线等式。原子登记变更在序列尾加一条记录，并同步发布 `fold` 的下一个状态。追加 DENY 保持状态值。写入扩展 `w`，成功的刷写至多把 `d` 推到开始刷写前捕获的连续 `w`。数据库仅按顺序原子处理下一个已确认记录，因此 `b` 前进一步后仍满足 `DBFacts = R(b)`。响应门只在对应前缀与绑定可验证时产生上述成功或 403，错误或未知不推进确认边界。若崩溃后确认保留有效前缀 `r` 且 `r ≥ d`，则由 fold 的连接律，`fold(R(b), L[b+1..r]) = R(r)`。只有对账并核验完整性后才开放服务。恢复也可能接受已实际落盘但尚未获响应的完整记录，操作缺席本身不能推出它从未发生。∎

A/A1 允许普通读在治理变更已发布且尚未刷写时使用新授权。该授权可能因崩溃丢失，其业务效果不会自动撤销。因此论文应分别陈述运行时准入安全和相应响应的持久前缀保证。使用持久线性化作为整套系统的定理时，尚需另证崩溃前后的外部操作历史满足其定义。

## 4. 目标协议与实现的精化义务

| 义务 | 当前可核查的实现与缺口 |
|---|---|
| 从刷写到连续文件前缀 | `ensure_durable` 只确认开始刷写时已注册的写入边界，检查文件长度并保留失败状态。这是对文件前缀的证据。硬件故障假设、截断与缺失历史的独立锚点需要另外验证。 [刷写协调器](../../astral-single-node/src/memory_v1_durable_journal.rs#L349) |
| 治理发布到日志顺序 | 当前 owner 先写入并确认日志，释放日志锁后再尝试根发布。正式写者重新读取当前元数据作为 CAS 条件，尚未建立它与最初授权观测一致且与日志串行顺序相同的证明。失败发布与已落盘记录之间需要清楚的提交与恢复判据。 [提交 owner](../../astral-single-node/src/memory_v1_governance_owner.rs#L165) · [正式写者](../../astral-single-node/src/memory_v1_root_writer.rs#L115) |
| DENY 状态对应的持久前缀 | 当前两个证明由同一条 DENY 回执构造。状态前缀证明仍依赖独立的映射，把读到的 `(根实例, 版本, 摘要)` 绑定到真实已应用变更前缀。 [DENY 证明构造](../../astral-single-node/src/memory_v1_governance_owner.rs#L414) |
| DB 与恢复的一致性 | 当前恢复从捕获的候选根向内存顺序重放，要求第 `n` 个变更的前置版本为 `n−1`，然后采纳。等式 `DBFacts = R(b)` 及从已核对的 `b` 出发先补齐 DB 的事务协议需要独立实现和验证。 [启动恢复 owner](../../astral-single-node/src/memory_v1_recovery_owner.rs#L76) |

## 5. 可复现证据及边界

```bash
cargo test --locked --offline -p test-harness --test memory_v1_authority_model -- --nocapture
```

[Rust 模型](../../test-harness/tests/memory_v1_authority_model.rs) 从初态广度优先枚举整个有限图。读模型使用一个请求、四个受检维度和一个无关维度，各代际从 0 至 2，时钟从 0 至 3，栅栏以采样切点上的状态抽象。首批结果为 940,896 个状态、5,117,256 条转换，其中 288 条为允许复核。测试检查每个允许切点的独立准入谓词、各维度单独失效、无关变更和改回原值。栅栏双观测的内部并发由实际组件测试覆盖。

日志模型使用一个 owner、至多两次治理变更、一次 DENY 观测和一次崩溃恢复。它枚举发布、写入、合并刷写、未知刷写结果、数据库前进和有效前缀恢复。首批结果为 2,969 个状态、4,623 条转换。测试要求治理确认、零前缀 DENY、延后 DENY、批量刷写、未确认记录留存和未持久状态丢失均实际可达。枚举核查抽象转换与不变式在所列边界内的一致性。数学归纳给出抽象协议的任意有限历史性质，源码精化、存储故障、活性与公平性需要各自证据。性能不由安全定理推出。

## 6. 学术定位

- Herlihy 与 Wing，*Linearizability: A Correctness Condition for Concurrent Objects*，TOPLAS 1990。本文用其调用与返回区间内的线性化点概念，限定到正向准入的安全性质。 [论文](https://doi.org/10.1145/78969.78972)
- Abadi 与 Lamport，*The Existence of Refinement Mappings*，TCS 1991。实现证据需要从具体状态与事件映射到抽象状态与步骤，并验证观测保持。 [论文](https://doi.org/10.1016/0304-3975(91)90224-P)
- Izraelevitz、Mendes 与 Scott，*Linearizability of Persistent Memory Objects under a Full-System-Crash Failure Model*，DISC 2016。本文参考其跨崩溃历史的分析框架，并以本地文件可靠刷写和服务操作响应定义自己的证明边界。 [论文](https://www.cs.rochester.edu/u/scott/papers/2016_DISC_persistence.pdf)
