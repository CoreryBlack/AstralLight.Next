# memory-v1 请求生命周期与共享根读取设计

> 状态：目标设计，2026-11-12；请求级读者、模块接线、缺失补齐和正式授权尚未完成实现或生产验收。工程合同以 [Rust 规范 §15.10](../规范/Rust后端编码规范_V1.0.md#1510-memory-v1-单机内存权威合同2026-11-12) 为准。
>
> 范围：单个受监督组合进程中的一次受保护请求，从 Gateway 接收、认证和清洗，到引擎判断、业务操作、响应及资源释放。公开认证入口及无需授权根的请求按各自协议处理，不为套用本设计虚构身份卡或授权上下文。

## 1. 一个请求，一个请求级读者

一次受保护请求有一个完整生命周期。生命周期内，组合入口在首次需要根事实时创建一个 `RequestRootReader`；同一进程中参与该请求的 Gateway、Identity、TrustGraph、PolicyEngine 和业务模块，按实际调用路径共享这个读者，直接读取同一个根的一致视图。模块只使用职责和请求范围所需的类型化只读接口；并非每个请求都会调用所有模块。

Gateway 接收请求后可以先执行清洗、凭证和协议校验；若认证过程需要根事实，在首次读取前建立读者。尚未认证的输入只是待验证参数，不能凭客户端自报的身份、租户、卡或资源扩大读取范围。任何模块都不得自行重新开始一次读取并将其结果与本阶段的读者结果拼成一个授权上下文。

```text
进程：RootOwner ── 当前共享根 ── 模块长期复用的只读 RootHandle
                                      │
请求 A：接入/清洗 → 请求读者 A → 按实际路径共享 → 复核/操作 → 结束并释放
请求 B：接入/清洗 → 请求读者 B → 按实际路径共享 → 复核/操作 → 结束并释放
```

`RootHandle` 是进程内只读能力；`RequestRootReader` 是请求上下文持有的读取能力，不是新根、线程或读锁。不同请求各有自己的读者，同一请求中模块借用同一读者即可。若请求在尚未读取根前即被拒绝或取消，不必创建读者。跨进程或网络调用不能传递 Rust 引用、`Arc` 或只读能力：跨边界协议、身份验证、请求关联和另一进程如何取得自己的授权事实均需单独设计；不能将本单机合同宣称为跨进程共享根。

## 2. 生命周期与职责

1. **接入与认证**：Gateway 接收请求，清洗客户端伪造的内部身份元数据，验证适用凭证；下游验证网关身份元数据的签名、时间戳和来源。认证或协议失败时结束，不进入业务放行。
2. **建立读者**：首次需要根事实时，从同一 `RootOwner` 的只读句柄取得一个请求级读者，绑定请求关联标识、根实例、版本、预存内容 hash、状态及必要的时间观察；身份和租户在各自可信校验完成后绑定。标识只用于关联，不代替身份或授权。
3. **一致读取与评估**：参与模块在同一个读取阶段按职责查询预建关系；引擎取得本次判断所需完整上下文，包括用户、双卡、租户、已确认绑定、规则、可信资源归属及适用限制，并由 `PolicyEngine.evaluate()` 判断。读取事实、认证成功或持有读者均不等于 ALLOW。
4. **最终复核**：ALLOW 前由授权链核对同一根的实例、版本、预存 hash、状态及可信时间，检查本次判断的有效期；不重新遍历完整关系或重算完整 hash。变化、失效、时间条件无法确认或 owner 消失时，本次判断不得放行。
5. **操作与结束**：通过复核后按本次授权执行对应操作，并按协议响应；成功、拒绝、异常、取消和超时均结束请求并释放读者及其读取视图。业务操作及其数据一致性仍由业务 owner 负责；管理变更须按 §5 再做受限提交检查。

该最终复核是用户确认的本次授权判断边界；撤权在复核前发布则旧判断不能放行，复核通过后发生的撤权不追溯否定本次已通过判断，后续请求重新授权。**复核与随后业务副作用不是自动原子绑定**：如果业务操作还需要对业务数据、资源归属或提交条件做一致性保证，必须由该操作合同单独明确并验证，不能仅以根元数据相同证明业务提交安全。

## 3. 并发读与资源生命周期

目标实现可以采用 `ArcSwap<RootSnapshot>` 和不可变、结构共享的 HAMT：每位请求读者在读取阶段原子取得一次当前快照，然后在其上遍历关系；读者互不需要根级读锁。经授权的写入在唯一 owner 下构造一致的新状态，通过 CAS 或等价协议原子发布；两个从同一版本出发的写入不能相互覆盖。快照 `N` 的在途读者和快照 `N+1` 的新读者可以并行，旧视图只是被引用的历史读取状态，不是可独立提交的第二权威。最终复核比较当前元数据；全局版本变化即使与本请求无关也使旧判断失效。

句柄数量由模块装配决定；活跃读者通常与已进入根读取阶段的在途请求数量相关，而不是模块数量。多个读者可引用同一个快照，不按请求复制整棵根；引用计数、HAMT、快照替换和共享节点仍有运行成本，不能据此声称完整请求链无锁或零开销。请求完成后读取视图应及时释放，旧快照仅在不再被任何持有者引用后回收。

必须设置可执行的请求并发、排队长度、等待与执行时间、补齐并发及内存预算，容量不足时按接口合同过载或安全失败；监控活跃请求、读者持有时间、旧版本保留和内存压力。普通并发请求不要求互相等待；发布及重试的资源策略须兼顾撤权，不能将一律暂停写入或优先放行旧读者当作默认策略。禁止强制回收仍被引用的快照。

请求取消、超时或客户端断连须传播取消并释放请求拥有的读取引用；被派生任务、流式响应或其他引用持有时，不能仅凭请求处理函数返回就声称快照已回收。实现须限制、取消或等待这些工作，记录实际回收和资源上界；长连接、流式和后台工作的具体生命周期与再次授权边界在采用前确定，不能无限期继承一次 ALLOW。

## 4. 未加载上下文的受控补齐

读取区分完整、已证明不存在、未加载、无效和不可验证。只有确实未加载且范围可确定时，本请求才可触发根协调器进行有界 MySQL 一致性读取；数据库行不直接用于 ALLOW。相同缺失范围可合并并发读取，但仍需验证每个请求的身份、租户和范围。

```text
请求读者，读取阶段 N → 发现未加载 → 丢弃该阶段的授权判断及派生结果
    → 受控查库、验证关系和租户 → owner 检查并发及内存冲突
    → 原子补入同一根 → 同一请求读者受控进入新阶段 N+1
    → 从新阶段重新读取所有授权依赖并重新评估 → 最终复核
```

读者逻辑身份和请求生命周期不变，底层读取阶段可以更新；刷新必须由请求协调路径独占执行，先结束或取消仍使用旧阶段的并发分支，不能让模块同时混用两个阶段。刷新前释放不再需要的旧引用；任何已从旧阶段派生的身份、范围、匹配、决策或管理授权都必须重新验证，不能与新阶段数据拼接。其他请求的读者不受该请求的阶段切换影响。

补入前核对同一根实例、缺失范围、版本和当前内存事实；DB 可能落后，不能覆盖较新内存事实或复活撤销、删除。冲突、安全合并无法证明、取消、超时、容量耗尽或未知结果时 PENDING/DENY；明确不存在且范围完整时按规则拒绝。重试须有上限，具体覆盖证明和合并协议见[单机唯一共享根设计](单机唯一共享根设计.md)。完整的后续请求直接读根，不查 DB。

## 5. 管理请求

```text
Gateway → TrustGraph 构造管理意图 → 同一请求读者读取根
    → PolicyEngine.evaluate() 判断具体管理操作 → 最终授权复核
    → TrustGraph 调用与该授权绑定的受限写能力 → RootOwner 原子提交 → 响应
```

授权绑定操作者、具体动作、目标范围、变更摘要、稳定 `operationId` 和观察到的根实例及版本；根提交时核验授权有效性、目标和摘要、重放及 CAS 前提，失败则不提交并重新发起完整评估。只读者无法转换为通用写能力。管理变更成功后原读者仍观察旧阶段；如需读取提交后的状态，受控进入新阶段并重新读取，不得把旧观察说成当前状态。内存提交成功不证明 MySQL 或审计已经落盘。

## 6. 采用与验证

当前实现（2026-11-13，候选，未采用）：单机组合候选 `MemoryV1Composition` 已打通一次完整的受保护请求生命周期，并由隔离 Rust 验收测试覆盖。（1）Gateway 在认证前清洗客户端伪造的内部身份头；`m1.*` 不透明会话凭证不再交给 JWT 解码，而由组合注入的 `MemoryV1SessionVerifier` 在接入路由验证（无效、畸形、过期或撤销为 401，会话权威不可用为 503），且只在进程内组合中接受、不注入任何旧身份头；非组合模式与非接入路由一律拒绝。（2）进程内分发在缓冲请求体之前经组合持有的 `RequestRootBudget` 准入每个请求作用域：耗尽立即 503、不排队，作用域及其全部读者租约释放后才归还名额；随后持会话权威读锁复核凭证并绑定到该作用域。只有绑定成功且目标为带 memory—v1 守卫的 TrustGraph 时才发出会话传输标记，Identity 等仅旧路径目标继续要求旧主体。（3）下游进程内来源校验把该标记转换为不可外部构造的 `VerifiedMemoryV1SessionTransport`；旧 v3 验签仅在“该标记且全部旧身份头为空”时按身份为空传输处理，仍校验签名与时间戳，混入任何旧身份头即拒绝。（4）TrustGraph 权限中间件对携带请求根作用域的请求只走 memory—v1 分支：先要求路由属于已适配 memory—v1 的白名单（当前仅 `GET /main/api/v1/permission-rules/registry`；其余路由及全部变更在受限管理写路径实现前一律 PENDING，绝不以空旧身份运行旧处理器），再要求会话绑定同一作用域且经已证明的会话传输到达，冻结操作标识与请求指纹后调用 `PolicyEngine::evaluate_memory_v1`。（5）引擎在该请求读者的同一阶段读取用户、双卡、租户、已确认绑定与规则集，要求根为 Serving，任一匹配 DENY 优先，ALLOW 前复核根元数据与可信时间，并生成绑定根版本、身份、资源、动作、目标、操作标识、指纹与可信时间的 admission；ALLOW 后处理器执行，DENY 为 403，PENDING 为 503，不回退旧路径。（6）Gateway 收齐响应后释放作用域，读者与预算名额随之释放。（7）Identity 提供 `MemoryV1IdentitySession::login`：先校验凭证，再用本次登录自己的请求读者在 Serving 根中核对所选用户卡与用户、身份卡、租户的关系，之后才签发会话；未知卡与他人卡同样拒绝，`revoke` 用于登出。HTTP 登录与会话管理路由在正式路径仍未接线，以免分叉已冻结的 `/api/v1/auth/sessions` 协议；仅下述显式实验 profile 在回环监听上提供登录与登出。

验收证据：`astral-single-node` 的隔离测试 `memory_v1_composition::full_path_tests::full_path_lifecycle_request_isolated_process`（`src/memory_v1_full_path_tests.rs`） 经真实 Gateway、真实 TrustGraph 路由与权限中间件、引擎及真实处理器完成一次 ALLOW 请求（200），验证同一读者贯穿下游生命周期、伪造头被清洗、凭证不越过分发、响应后读者释放且预算归零、每个请求各有读者；并覆盖 OVERLAY DENY 与未绑定卡 DENY（403）、未适配路由与变更 PENDING（503 且不评估）、仅旧路径目标拒绝空身份、撤销/缺失/畸形凭证在 Gateway 401 且不评估、根 owner 消失 503。该测试的根通过仅测试可用的 `test-support` 特性（只能经 `[dev-dependencies]` 启用，resolver 2 下不进入任何非测试构建）走真实的快照绑定校验与 CAS 发布被采纳为 Serving；它证明请求生命周期接线与失败关闭，不证明数据库来源、完整覆盖、确认人权限或生产采用，也不开放 listener。

**统一启动（2026-11-14 用户决定）**：本分支移除实验/正式双启动模式——memory-v1 服务即唯一启动/生产路径，`ASTRAL_SINGLE_NODE_PROFILE` 环境变量与正式路径的就绪拒绝退役，feature 门（memory-v1-candidate）一并移除；采纳等级（Experimental）、十类未证事实族的运维确认、凭据文件与回环监听等启动门禁照常，真实部署前的生产采用证据链（§15.10.5）要求不变。以下段落保留为该统一路径的机制描述。

实验真实服务（2026-11-13，显式实验，不是生产采用）：`astral-single-node` 在 `ASTRAL_SINGLE_NODE_PROFILE=memory-v1-experimental`（名称精确匹配，其他非空值一律拒绝）下运行 `memory_v1_service::run`，使一次生命周期请求能由运行中的真实进程经 HTTP 完成；正式单机路径未开放 listener：其启动先经只读预检读取候选库并报告仍不能证明的事实族（见下方“正式启动预检”段），之后仍以就绪拒绝（`memory-v1 authorization root is not ready for a listener`）照常拒绝。（1）配置经命名的实验加载入口，只跳过 `MemoryV1ProfileNotReady` 这一就绪拒绝，身份、HMAC、CORS、本地库等其余安全门照常；必须 `ASTRAL_MESSAGE_TRANSPORT=local`；凭证来自权限 0600 的私有文件 `ASTRAL_MEMORY_V1_CREDENTIALS_FILE`（只检查 Unix 模式位，不检查 ACL 授权），不读数据库。（2）监听只允许回环地址，非回环在任何文件或数据库访问前被拒绝，绑定后再核对一次。（3）冷加载在一个 `START TRANSACTION WITH CONSISTENT SNAPSHOT, READ ONLY`（REPEATABLE READ）事务内读取九张 `memory_*` 表，校验 schema 清单并在同一快照内 `COUNT(*)`；冷加载后关闭连接池，服务不再访问数据库。（4）`RootOwner::adopt_experimental` 以 `Experimental` 等级采纳：重新推导各表行数（快照 `COUNT(*)`、扫描、根内行与元数据四者一致）、每个规则集恰有一个存储版本、schema 合同版本与指纹非零；其余十类事实族（来源、快照身份、生命周期与有效期、确认权威、资源归属、资格、职责分离、写者覆盖、审计关联、持久化与恢复）仍为 `Unverified`，仅当运维在 `ASTRAL_MEMORY_V1_ACKNOWLEDGE_LIMITS` 中逐一点名才放行，并写入服务快照中的采纳记录与就绪行。（5）TrustGraph 在离线连接池上构建，未适配路由返回 503 `AUTHORIZATION_PENDING`，不会回退旧行。（6）Identity 只提供 `POST /api/v1/auth/sessions`（登录）与 `POST /api/v1/auth/sessions/logout`；Gateway 对凭证路由策略为 AccessOnly 或 AccessOrRefresh 的路由接受不透明会话（首次真实套接字运行发现登出被 `TOKEN_ROUTE_MISMATCH` 拒绝，已修复；仅刷新与公开路由仍拒绝）。（7）就绪行 `ASTRAL_MEMORY_V1_READY addr=… grade=Experimental root_version=… rows=… unverified=…` 只描述采纳内容，不是授权证据；收到 SIGTERM 或 Ctrl-C 后有界排空，根 owner 最后释放。

实验服务验证证据：（a）进程内回环 TCP：`memory_v1_service::lifecycle_tests::real_service_lifecycle_over_loopback_tcp_isolated_process`（夹具根，使用与 `run` 相同的 `adopt_rows` → `assemble` → `serve`）完成登录→授权读→拒绝→pending→登出→有界排空，另有未确认限制即拒绝采纳的用例。（b）真实二进制拒绝用例（`astral-single-node/tests/memory_v1_service_process.rs`，7 例，无数据库）：正式路径仍拒、未知 profile、非回环监听、缺凭据文件与未知限制名、0644 凭据文件、不可达数据库，均不输出就绪行；另有一例只解析 URL、不连接，检查端到端回环守卫接受括号 IPv6 并拒绝远程主机。（c）真实 MySQL 端到端（同文件，`#[ignore]`，需 `ASTRAL_MEMORY_V1_E2E_ADMIN_URL` 指向回环 MySQL，创建并删除唯一的 `astral_rehearsal_mv1_<16hex>` 库）：2026-11-13 经用户批准在远程 MySQL 8.0.46 测试服务器上经 SSH 端口转发执行。首次运行暴露 loader 把 `CHARACTER_MAXIMUM_LENGTH` 按 `BIGINT UNSIGNED` 解码、而 MySQL 8 返回有符号 `BIGINT` 的缺陷，已改为显式 `CAST(... AS UNSIGNED)` 并加守卫测试；复跑通过：应用已审查候选 DDL，参数化写入 21 行夹具，真实二进制冷加载并监听回环端口，经 HTTP 完成登录、授权读、OVERLAY DENY 与未绑定卡 403、未适配路由 503、登出后令牌 401；确认冷加载后该库无服务连接，SIGTERM 优雅退出且退出码 0，库被 DROP 并核对不存在，另两个受保护库的表清单前后一致（另由只读清单独立复核）。该证据证明 loader SQL、DDL 抽取与“冷加载到真实 HTTP 服务”的整条链路能在真实 MySQL 上运行；数据是手工夹具，不证明数据来源、完整覆盖、确认人权限、生命周期与有效期、持久化与恢复，也不构成生产采用，更不开放正式 listener。

正式启动预检（2026-11-13，只读，不开放 listener）：`astral-single-node` 正式路径在就绪拒绝之前，以 `AppConfig::from_files_for_memory_v1_preflight` 加载配置（执行身份、HMAC、CORS、本地库等全部启动门，仅跳过就绪拒绝），再由 `memory_v1_preflight` 从一个一致快照读取候选库，经进程根安装器安装，调用 `RootOwner::unproven_production_families` 报告生产等级仍不能证明的事实族（当前为十类：来源、快照身份、生命周期与有效期、确认权威、资源归属、资格、职责分离、写者覆盖、审计关联、持久化与恢复），并在返回前释放根。报告非空即拒绝并列出全部事实族；报告为空也仅表示全部族已证明，其后仍由 `validate_listener_for` 就绪门拒绝。预检不采纳、不发布、不服务，也不改变根状态。验证：根层与单机层隔离测试、进程级不可达库用例（先读库后拒绝）；未在真实 MySQL 上运行正式预检，需用户另行批准。

仍未完成，不得据此开放正式 listener：生产采用证据链（`AdoptionEvidence` 无生产构造；正式单机路径仍不使用该组合，仅显式实验 profile 使用）；服务期缺失补齐及读者受控阶段刷新（读者从不刷新，已捕获阶段失效只能使本次请求 PENDING）；管理请求的受限写能力与根 CAS 提交；正式路径的 HTTP 登录与会话管理，以及实验 profile 中尚未提供的刷新、撤销与切卡路由；其余 TrustGraph 处理器的 memory—v1 适配与可信资源归属；长连接与流式响应的作用域生命周期；跨进程 HTTP 传输仍不能携带读者。断路器对 PENDING 的处理（2026-11-13）：进程内 TrustGraph 的 503 PENDING 经分发器核验 `AuthorizationPendingRefusal` 标记后计为成功，突发 PENDING 不再打开断路器；跨进程 HTTP 传输不携带该标记，届时须另行设计可验证的响应标记。Gateway 本地产生的 503（容量耗尽、会话绑定失败）仍按状态码计入断路器，待另行决定。
