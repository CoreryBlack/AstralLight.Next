## 1. 读法与口径

1. **类别（C）**：规范:1483 的句子“正式采用前必须完成：……等合同”按原顺序列出的 11 项，编号 C01–C11 已写入该句（2026-11-14）。句末的“等”表示该列表不一定穷尽，新增类别自 C12 起顺延。
2. **族（F）**：`AdoptionEvidence::families()`（`adoption.rs:268-328`）按决策顺序返回的 13 项。每项状态为 `Proven`、`Unknown` 或 `Unverified`（`adoption.rs:31-40`）。生产等级要求 13 族全部 `Proven`，且生产等级目前没有构造器（`adoption.rs:5-11`）。F01–F13 是本文按返回顺序加的次级标签，规范和代码里都没有；引用时优先写类别编号加族显示名（见 §6）。
3. **可豁免**：只有实验等级可以豁免，且须在 `ASTRAL_MEMORY_V1_ACKNOWLEDGE_LIMITS` 点名对应的 `AdoptionLimit`；F03–F05 没有对应项，永不可豁免。
4. **非族机制**：不在 13 族内、但门禁或请求路径已经机械强制的检查。可信时间是门禁里的独立检查（`adoption.rs:402-407`），不是族。
5. 本表中“无测试”“无实现”只表示在 §9 所列文件与检索范围内未检出，不是全仓结论。

## 4. 类别明细（锚点与测试）

### C01 规则语法与冲突

- 规范：:1449（精确匹配、冲突、确认有效范围“未冻结”）、:1453（hash 的算法与编码“须在实现前冻结”）。
- 设计待决：`权限引擎:191-193`、`双卡:170`、`规则集:168-169`、`新库:60`。设计与规范都写 OVERLAY 的明确拒绝可阻止相应 BASE 允许（规范:1449、`权限引擎:15,133`、`规则集:78`），而代码判定对绑定层无感（见下条）。
- 代码：闭集语法 `deny_unknown_fields`（`rules.rs:21,29`）；`MAX_RULES`、`MAX_TEXT_BYTES`（`rules.rs:10-11`）；`parse_version` 校验规范字节与 SHA-256 后解析（`rules.rs:110-132`），构建候选时对每个选定版本调用（`hamt.rs:587`，失败为 `RuleIntegrity`），求值时再解析（`formal.rs:214`，失败为 PENDING）；同一规则集内精确相等匹配、DENY 优先（`rules.rs:87-106`）；跨绑定累计 allow/deny，无 ALLOW 即 DENY（`formal.rs:194-227`）。
- 代码事实（规范与设计均未写）：遍历绑定时，任一绑定未选版本、确认不匹配或解析失败即返回 PENDING，即使前面的绑定已命中 DENY（`formal.rs:196-216`）；`evaluate_binding` 区分绑定层（`rules.rs:149-165`）但全仓无调用方，判定路径不读绑定层。
- 测试：`rules.rs:198`（`validates_hash_and_overlay_deny`，该文件唯一测试；用例只走通过路径：解析一条 ALLOW 规则并校验版本 hash 通过，不含 DENY、绑定层或 hash 不符）、`formal.rs:397`（`formal_rules_and_root_recheck`，该文件唯一测试函数）。未见按“未知字段、超限、冲突”逐项的拒绝用例。
