### 6.2 P3 发现：freshness gate v1 写突发自饥饿（重要）

**现象**：初版门禁（任何未发布 delta → PENDING）下，风暴仅 2 ops /
16,965 errors（p50 2ms 快速 403）+ 熔断打开。三节点复现最小化：3 线程 × 10
add，21/30 失败，响应体 `AUTHORIZATION_PENDING for permission_rule:create` →
`CIRCUIT_BREAKER_OPEN`。

**根因**：写请求的权限检查本身是一次证据读。写突发期间，前一个写的未发布
delta 把后一个写的权限检查打成 PENDING → 403；探针 `FOR UPDATE` 又与
projector 发布事务在 delta 行锁上互饿（发布需行锁推进 SUCCEEDED），形成
"未发布窗口越长 → 403 越多 → 探针越密集 → 发布越饿"的正反馈。

**重设计（v2，`b292337c`）**：

1. **谓词收窄为撤权类**：`event_type IN ('REMOVE','REVOKE')`（授权移除/吊销，
   旧证据继续放行即 stale-ALLOW——唯一不可接受方向），或 `revoke_fence` 超前
   本卡已发布水位（fence-raising 变更未落地）。ADD/UPDATE 类未发布 delta 不
   阻塞：缺新授权只是 deny-biased EC 的 ms 级漏授权窗口（既有语义，发布即收敛）。
2. **非锁定一致性读**：探针作为严格 reader 事务的第一条语句建立读快照，不与
   发布者争 delta 行锁；线性化由既有双读纪律 + ALLOW 前复读（新事务重跑整个
   协议）承担，与指针移动语义一致。
3. 保留不变：只挂正式证据读入口（projector 路径不持门，源码守卫钉死）；
   QUARANTINED 撤权类 delta 持续 PENDING（人工对账前不放行）。

**诚实残余边界**：收窄型 UPDATE（不抬 fence、非 REMOVE/REVOKE）存在发布延迟
内的收窄窗口——既有 deny-biased 取舍的既有口径；如需闭合须扩展"fence 语义覆
盖收窄变更"（产品决策，未批准，见 §十二）。

**口径警示**：P3 新旧数字不可直接比大小——基线 28.5 ops/s 的 573 ops 因 F6
缺陷**从未发布**（无发布争用）；本次 149 ops 全部真实发布并竞争投影锁。专项
明细（基线对照全表、延迟分布、口径分析）见
[`PERF_20260901.md`](PERF_20260901.md)。

## 八、战役产品缺陷闭环（发现 → 根因 → 修复 → 验证）

### 8.1 兄弟尾阻塞（10.D-2）

- **现象**：高 churn 聚合上同 grant 多条未发布 delta 时
  `claimed_behind_unpublished_siblings` 确定性阻塞，叠加发布事务 1213 死锁
  重试（瞬态），高 churn 卡排水依赖 900s 退避周期。
- **根因**：`attempts = attempts + 1` 在**认领时**写入——后继 delta 只要被
  认领即烧预算，而其分区器判定必然 Blocked（per-grant 链不可跳过未发布前
  驱）；预算 5 耗尽后按最大退避停摆。认领排序又跳过有退避的哥哥 delta 先领
  弟弟，形成级联。
- **修复**：`614ba2d0`（认领侧兄弟门 + 看门狗同形）+ `7e55c0a7`（索引与契
  约解析器）+ `1022bd7b`/`24eea212`（集成测试）。
- **验证**：集成 7/7（真库，§十）；CS 全套 9.4s 零积压；QUARANTINED 前驱路
  径保持可观测（Blocked/budget 路径不静默）。

   聚合指针；败者在竞争窗内烧尽 5 次 attempt 预算 → 900s 退避停摆
   （fail-closed：卡作用域持续 PENDING），静默期后重试自愈收敛（实测 898s
   排水窗口全程、零 stale-allow）。add+del 交替的撤销重压形态下该机制使卡
   作用域持续不可写——v2 门禁语义正确的代价，产品级改进候选（PointerMoved
   类失败是否应消耗 attempt 预算）列 §十二。
3. **撤销重压最坏情形实测**：add+del 交替突发 100% 快速 403
   （`AUTHORIZATION_PENDING`）——每次 delete 的撤权类 delta 未发布前，后续
   写的权限检查被门禁正确拦截。属门禁设计语义，非缺陷。
4. scale_100/500 的 API 分布因 harness 中途崩溃未落盘，发布 p50 与优胜删除
   数字自运行日志抢救（`provenance` 字段已标注）。
