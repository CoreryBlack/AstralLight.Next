# 授权执行期能力曲线（2026-10-25）

> 日期：2026-10-25。采集状态：campaign 与 benchmark protocol `PASS`。这表示完整矩阵和后置条件均通过，不表示性能收益保证。
> 测量对象：本机 release-mode `PolicyEngine::evaluate()` CPU fixture。不是 HTTP QPS、生产容量、真实数据库/MQ 性能或跨引擎同拓扑 A/B。

## 1. 结论速览

本次完整测量覆盖 **45 个 case**（5 个 grant 规模 × 3 个线程数 × 3 种决策结果），每个 case 18 个配对批次，比较 3 个 arm，总计 **810 个 batch samples / 2,430 组 arm measurements**。controls、evidence contracts 和性能矩阵三个选定 suite 全部 `PASS`；45 个 case 的决策、读取计数均已核验，所有 workers 已 join，无重试或日志断流。

在本机 synthetic fixture 中，单 case pooled throughput 范围分别为：cached **3.396–729.849k**、forced-assembly **0.489–430.672k**、production-clock **3.396–729.309k decisions/s**。45 个 case 配对 forced/cached 决策延迟几何比为 **1.708–34.879**；cached/forced 吞吐比为 **1.654–32.374**。这表示该测量协议下两种受控组之间的观察差异，不应归因于单一 Arc 指针操作，也不等价于旧版本完整系统 A/B。

同协议的 2026-10-10 历史 raw matrix 中，2048 grants / 8 threads / allow-first / cached 的 pooled throughput 为 1.289k/s，当前为 16.390k/s；相应 P50/P99 是历史 5,630.333/8,492.417 µs、当前 282.083/1,241.791 µs。但 source SHA 不同；历史报告记录 macOS 26.5，当前分析环境观察到 macOS 27.0.1，且本次 canonical run JSON 未包含主机 OS 字段。因此这是协议相同但源码快照/OS 记录不同的观测比较，**不能据此将变化因果归于某一项代码改动或宣布生产性能提升**。

## 2. 测量口径与夹具

### 2.1 冻结矩阵

- grants：`1 / 8 / 128 / 512 / 2048`。
- OS worker threads：`1 / 4 / 8`。
- outcome：`allow-first`、`allow-last`、`deny`（DEFAULT_DENY）。
- arms：`cached-fixed-second`、`forced-assembly`、`production-clock`。
- 每 case 18 个配对 batch；6 种 arm 顺序各重复 3 次；不删除异常值。
- 每线程每批次决策数按 grants 固定为 `{1: 256, 8: 256, 128: 96, 512: 32, 2048: 16}`。

### 2.2 延迟与吞吐定义

**Latency P50/P99** 是该 case 的原始 `latencyNs` 合并分布分位数，样本覆盖全部 batch 和 workers；每个调用从进入 `PolicyEngine::evaluate()` 到 awaited `PolicyDecision` 返回计时。返回之后的决策核验、写入结果记录和对象销毁不计入该延迟值。报告按 microsecond 展示；harness 使用 nearest-rank 位置 `ceil(n × p)`（从 1 起计数），P50/P99 与 canonical summary 一致。

**Pooled throughput** 按该 case 18 个 batch 的总决策数除以累计 wall time 计算。wall time 包含 barrier 唤醒、结果核验/存储/销毁及 worker join，不包含 thread/runtime 构造和 cache prewarm。吞吐值不是 `1 / latency`，不代表 HTTP 请求吞吐或服务 QPS；P50/P99 与吞吐的计时边界本就不同。

### 2.3 Fixture 与 arm 语义

合成 fixture 为单个 `PLATFORM_USER` 身份：identity `18`、user `42`、card `17`、tenant `7`、domain `11`；资源归属是服务分类的 tenant-scoped tenant `7`/domain `11`，ORG fixture 为 `Unmanaged`。grants 为永久有效、单卡且作用域固定。测试保留完整 engine stats、breaker overhead、token recheck 和相同的共享 tick 成本。

| Arm | 条件与解释 |
|---|---|
| `cached-fixed-second` | 固定 validity second，保留真实 1 秒 TTL；预热后 ALLOW 两次 evidence 读取应命中装配缓存。 |
| `forced-assembly` | 每次读取使用唯一 synthetic second，触发与生产 miss 相同的装配、refill 和 token recheck；不是移除生产缓存的另一套算法。 |
| `production-clock` | 使用实际 UTC 秒和实际 TTL；记录真正的 hit/miss，作为本机预热 fixture 下生产时钟参考，不代表真实请求间隔或 cache churn。 |

独立 controls 检查 decision parity、owned evidence parity、无 legacy reads、ALLOW 两读、DENY/PENDING 一读、跨秒过期、最终 revoke refusal 等约束。核心验证不以 early deny 冒充快路径，也不设最低速度/收益阈值。

### 2.4 未包含的路径

本曲线**不包含** Gateway/HMAC 签名、HTTP/socket、真实 MySQL identity/eligibility/ORG 查询、Redis/RabbitMQ、durable audit delivery、SDK 映射、下游业务 handler、managed ORG_SCOPE、分配计数、线上数据分布、source churn、负载隔离或 P/E 核利用率采样。因此不能将其解释为真实端到端请求性能、集群能力、生产容量、存储 TPS 或审计/MQ durable latency。
