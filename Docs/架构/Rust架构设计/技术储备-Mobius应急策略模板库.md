> 状态：**路线图储备；Mobius 专项设计、实现和验收均无证据。**本文件补充问题分解和待评审的候选架构，不是获批设计；下文所有机制选择均为候选，未获批准前不得作为产品合同。
>
> 对应：[技术能力与储备清单](../../技术能力与储备清单.md) 原 40；[Mobius 与技术储备定位](../../../index.html#panel-reserves)。

## 1. 技术问题与目标边界

路线图将 Mobius 定位为“全域审批调度编排层”，并把应急模板、临时授权生命周期、分级通知和自动到期列为相关方向。这里的难题不是保存一段可复制的规则文本，而是在紧急情境下把业务意图、审批证据、范围受限的 source mutation、后续投影、到期/撤销和结果核验串成一条可审计流程。人工临时操作容易出现对象范围不一致、模板更新后无法重现当时批准内容、审批和实际生效对象脱节，以及请求超时后不知道是否已提交等问题。

“模板库”应是可复用的应急处置意图与约束载体；它本身不是授权事实，也不应成为绕过授权 owner、租户边界、source transaction 或正式 `PolicyEngine.evaluate()` read-gate 的第二套规则引擎。具体应急场景、支持的资源/动作、谁可维护和批准、模板表达能力及 Mobius 与现有服务的边界，目前均没有专项决策。

## 2. 候选机制与生命周期（未批准）

以下仅用于让后续评审有完整对象，不代表已选择数据模型、API、状态名或流程：

1. **定义并评审模板**：候选模板包含场景说明、适用条件、明确的 tenant/domain 与目标主体/资源范围、允许提出的动作、最大有效期、所需审批证据、回退/核验步骤和通知意图。建议模板发布采用不可变修订；修订只影响新实例，历史实例固定引用其原修订，避免事后模板改动改变已批准请求的含义。
2. **实例化应急请求**：调用者提交场景事实、目标和理由，系统将其绑定到具体模板修订，生成稳定 `operationId`，形成待审批 proposal。实例须对目标租户、主体、资源/动作和有效期做显式边界校验；候选模板只提供约束与预填值，不应携带可执行 SQL、任意脚本或直接授予授权的隐藏表达式。
3. **审批和批准后执行**：由未来决策确定的审批人按模板版本和完整请求事实批准。执行适配器只能把获批 proposal 翻译为对应 source owner 已支持的 mutation；如果会影响有效授权，仍须走已批准的授权 source/evidence 路径、审计关联及其 durable 发布/read-gate。执行结果不等同于审批结果；projection 未证明时保持 `PENDING`/`DENY`，不能以紧急等级放宽授权。
4. **跟踪、到期、撤销与结案**：实例记录 source operation、审批与发布证据的关联；到期/撤销需调用相应 aggregate owner，而不能只改模板状态或依赖缓存 TTL。结案前核对 durable postcondition 和必要审计。各状态、审批门槛、调用者权限和自动动作仍待产品与安全评审。

### 候选取舍

不可变版本、proposal 与 source mutation 分离，有利于重现批准依据和审计；代价是要治理版本生命周期、模板迁移和过期模板。模板表达能力越灵活，越容易变成未受控的第二授权语言，因此候选方案倾向于有限声明式约束，并由既有业务 owner 进行最终校验；是否采用这种限制仍未批准。模板过于静态会让紧急处置无法覆盖新情况，过度灵活则增加误授权面，需以场景清单和威胁评审决定平衡点。

## 3. 失败恢复与安全边界（目标要求，未批准具体实现）

- 审批拒绝、模板/请求版本不匹配、目标范围缺失或租户归属无法证明时，不产生 source mutation；失败默认拒绝或保持待处理，不允许用“应急”标签兜底。
- source 提交后请求断流或结果未知时，必须用稳定 `operationId` 对账 source、事件/ledger、投影和审计状态，再决定继续；不能盲目重放、仅凭 ACK 或前端成功提示宣称生效。
- 投影、通知或审计后续步骤失败，不得把未证明状态报告为授权成功；通知只负责传递状态，不是审批或授权证据。到期/撤销路径须能处理 worker 重启、重复事件、并发批准/撤销和部分完成，并明确恢复责任人及人工补偿入口。
- 模板内容和实例数据应遵守最小权限、租户隔离、敏感信息最小化与可追溯访问；高权限模板维护、审批和执行不应默认由同一主体完成。签名、保留期、保密级别、分离职责及审批法定人数尚未决策。

## 5. 进入正式设计的门槛

在批准任何实现前，至少要确定应急场景及排除范围、模板 owner/版本策略、实例与审批主体、授权 source mutation 映射、审批与执行的职责分离、有效期语义、到期/撤销和未知结果恢复、通知与审计契约、迁移/回滚方案及验收环境。验收须覆盖拒绝、重复提交、并发审批/撤销、超时未知、projection 延迟/失败、租户交叉和模板新旧版本；实际验收标准和环境由专项设计批准时确定。
