# 异构存量权限系统统一接管：储备范围与证据边界

> 状态：**规划储备；未找到面向任意存量权限系统的通用迁移/适配框架。**本文是储备专题说明，不是数据迁移、映射或生产切流设计。
>
> 对应：[技术能力与储备清单](../../技术能力与储备清单.md) 原 47；[SDK 接入 V1](../../SDK接入V1.md)、[SDK V1 实施证据](../../SDK接入V1_实施证据.md)、[Rust 迁移 Java 等价适配状态（2026-08-05）](../../迁移/Rust迁移Java等价适配状态_2026-08-05.md)。

## 1. “统一接管”包含什么

对异构存量权限系统的接管不是只导入用户、角色或规则行。不同系统可能有不同主体身份、资源层级、租户语义、拒绝优先级、时间有效性、规则继承、审批状态、审计和撤销方式。要接管其权限，必须有可证明的语义映射，并持续处理 source mutation、版本推进、身份/资格变化、失效、回滚与未知结果。

本储备没有给出目标系统协议、导入格式、转换函数、过渡双写或切流流程，因此不应把它表述为现成产品能力。

## 2. 当前可见的相关能力

- SDK V1 提供已注册应用的远程授权接入合同，但要求显式 actor/facts resolver、应用范围和 owner 事实。
- SDK 身份映射是管理员把 `(app_id, issuer, subject)` 绑定到**已有**平台用户和身份卡；不会按邮箱/手机号自动合并，不自动建用户/卡，不把旧角色转换成授权。OAuth/OIDC 等任意 IdP 接入仍关闭。
- 2026-08-05 的 Java 等价适配账本记录了特定服务/日期范围内的修复与待验证项。它不是对任意第三方权限系统的通用 adapter，也不能证明当前所有系统整体等价。
- 授权决策仍要求进入唯一 PolicyEngine 入口，并遵守 strict evidence 与租户边界。

## 3. 问题分解：身份迁移不等于策略迁移

“接管”至少包含两个彼此独立、不可互相推导的迁移面：

- **身份/主体映射**回答某源系统 issuer/subject 是否对应到哪个已存在的平台用户和认证身份。它涉及身份校验、绑定唯一性、禁用/撤销状态与映射生命周期；不迁移凭据，不创建授权卡，也不把旧角色转成平台权限。
- **授权策略语义映射**回答源系统中的 principal、resource、action、effect、条件、层级、优先级、时效和拒绝规则，能否在目标模型中表达并保持相同结论。映射主体成功不代表策略可表达或授权已授予。

接管对象还可能把角色、组、资源路径、组织关系、策略脚本、审批状态、委托、临时授权和数据行约束混合在一起。必须先盘点实际决策路径与 owner，不能把“导出表成功”当作语义保真证明。`ORG_SCOPE` 是有明确租户/行政治理边界的授权扩展，不是通用策略导入或转换器。

## 4. 候选接管形态与语义映射分析（非决策）

单一通用转换器通常无法安全表达各源系统的差异。可供逐系统评估的候选包括：

| 候选 | 思路 | 适用性 / 收益 | 局限与必须保留的边界 |
|---|---|---|---|
| 源系统保留为决策权威、平台做受控联邦调用 | 以源系统 adapter 转译请求并转交源 PDP，回传带 source/revision/时间的结果 | 减少一次性规则转换；适于源语义复杂且源服务仍受支持 | 撤销和在线依赖仍由源系统控制；需要绑定调用身份、范围和请求摘要；超时/未知不能被解释为无权限或 ALLOW；平台决策和源决策可能冲突 |
| 针对某个源做版本化 adapter / 规范化投影 | 对可证明等价的子集做逐源转换，保留 source identity、原始值/来源、映射版本和未映射记录 | 可逐步纳入统一决策模型并做可重复 parity 对账 | 每个 adapter 均需源合同和语义测试；默认拒绝、继承、条件语言、时间和组织层级无法表达时不可强行降级；规范化可能丢失源特有语义 |
| 有限范围的受控导入与切换 | 经治理批准后，将明确的策略子集写入平台 source/evidence 路径，再分阶段移交决策权 | 有机会减少运行时依赖，支持最终单一 owner | 迁移是 source mutation；须防止双写分叉、遗漏撤销、回放乱序与切流时旧 ALLOW；需要逐租户/系统 gate、备份/恢复和正式验收 |

以上形态可按系统组合，但一个具体资源/租户的最终决策权威必须明确。双运行可以用于影子比较和差异观测；影子结果不能自动改变正式授权，也不能将较宽松的一侧作为 fallback。不存在已批准的通用转换器、统一优先级或默认切流步骤。

语义映射至少逐项核对：主体与组展开、资源类型/层次/归属、动作粒度、ALLOW/DENY/缺省行为、显式拒绝优先级、通配和继承、条件表达式、时间有效性及自然到期、审批/撤销/委托、租户和域边界、行级/字段级限制、审计与理由。对于不可表达或含义不明的项，应保留在隔离/待解释状态，并阻止受影响范围进入 ALLOW；不得丢弃条件后称为等价。

## 5. 冲突、撤销传播与回滚候选

**冲突处理**必须先定义 authority 与版本序，而非只设“平台优先”或“源系统优先”。源系统可能同时有直授、继承组规则和拒绝覆盖；导入目标又可能存在本地规则。需确定冲突发生在同一 resource/action 还是不同层级，拒绝是否优先，映射版本是否匹配。缺少可证明的优先级/版本关系时应呈现 UNKNOWN/PENDING 并拒绝受影响操作，而不是按行顺序或最近更新时间挑选。

**撤销传播**是持续集成合同，不只是迁移时同步一次。源端撤销、主体停用、组成员变化、规则变更和自然到期都要有可观察的 source revision/change cursor、稳定事件身份、重复/乱序处理、generation/fence 和读侧拒绝陈旧决策的条件。异步传播窗口内，若平台无法证明新版本已到达，不能让旧 ALLOW 继续生效。轮询、webhook/outbox、批量 reconciliation 是不同候选，必须依源系统的耐久性、顺序、删除 tombstone 和可重放能力评估；本文不指定统一协议。

**回滚**不仅是切回旧 API。若平台已接受新 source mutation，需确定这些变化是否也存在于原系统、冲突如何合并、旧端是否仍可接收撤销、投影如何重建以及未知提交如何对账。建议的分析门槛是逐租户/资源段保留已知 owner 与切流 marker，并定义暂停写入、重放/对账、generation 复核和恢复路径；迁移期间不得静默回退旧快照/raw source 以获得 ALLOW。具体迁移、备份和恢复必须另按适用迁移规范批准，本文件不形成执行授权。

安全威胁包括伪造外部主体、跨租户映射、权限扩大型降级、源端撤销后旧授权继续有效、映射绑定冲突、重放/乱序、漏同步删除、影子差异被误当正式决策，以及多系统审计无法关联。攻击者若能控制 source API 或 adapter 输入，系统必须用认证、签名/传输保护、受限映射、版本与内容校验阻断。误放行会扩大源权限或造成跨租户访问；误拒绝会影响可用性，应以受审计的重新同步/复核恢复。

## 6. 当前证据与批准状态

SDK V1 仅建立 `(app_id, issuer, subject) -> existing platform_user -> identity_card` 的受保护、管理员维护映射；不按邮箱等属性自动合并，不自动建用户/卡，不把角色转成授权，任意 OAuth/OIDC/IdP 接入仍关闭。SDK 的业务接入还要求应用范围、可信 facts resolver、owner 事实和本地 revision/CAS 复检。详见 [SDK 接入 V1](../../SDK接入V1.md) 与 [SDK V1 实施证据](../../SDK接入V1_实施证据.md)。这证明受控的身份绑定及远程授权合同，不证明迁移了源策略。

现有授权生产路径仍要求进入 PolicyEngine 且由 strict published evidence gate 验证有效证据；严格读门不能把“外部系统返回 ALLOW”当成不经约束的旁路。内部 canonical generation/fence 与 projection 的细节见 [增量重建与实时授权边界](Rust增量重建与实时授权边界_V1.0.md) 和 [投影快照与版本栅栏](Rust权限投影快照与版本栅栏_V1.0.md)。

[Java 等价适配状态账本](../../迁移/Rust迁移Java等价适配状态_2026-08-05.md) 只描述特定服务与时间范围的适配状态，不覆盖任意第三方产品。能力清单仍把通用异构接管列为储备。当前没有已批准的源系统清单、语义字典、全量 adapter、迁移/backfill、撤销时限、双运行切流、回滚或生产验收；测试和历史账本不能替代这些证据。

## 7. 专项立项前的证据门槛与结论

逐系统方案需先由 source owner 提供决策示例和数据字典，涵盖允许/拒绝/无规则、继承、冲突、租户边界、到期、撤销和身份生命周期；随后定义可表达子集、不可映射策略、source revision 与回放语义、差异容忍度、逐段 authority、审计关联和恢复演练。所需验收至少应覆盖 parity corpus、乱序/重复/延迟撤销、依赖不可用、权限冲突、跨租户攻击、未知提交和切换回滚。若缺关键事实则明确 BLOCKED/UNKNOWN，不以空结果充当 PASS。

本主题仍为未实施储备。身份映射、策略语义转换、数据迁移和正式切流是不同批准对象；本文给出候选及风险分析，不批准某种映射算法，也不声明任意存量系统已接管。生产数据迁移、schema/backfill 和外部切流不在本次说明执行范围。
