# 闲置异构算力编排：问题分析与候选架构边界

> 状态：**规划储备；当前没有通用异构资源发现、产品任务调度或闲置算力编排实现证据。**下述调度架构只是待批准候选，不是当前系统设计或性能承诺。
>
> 对应：[技术能力与储备清单](../../技术能力与储备清单.md) 原 44；[分布式授权集群测试说明](../../实验/分布式测试/README.md) 与 [`AuthorizationProjector` 配置](../../../astral-trustgraph/src/service/authorization_projector/config.rs)。

## 1. 技术问题与产品能力门槛

闲置异构算力编排要解决的是：从 CPU/GPU/ARM 或其他不同性能、指令集、内存/显存、设备和故障域的节点中，发现真实可用容量；基于任务要求、数据位置、租户/安全约束和优先级选择可执行位置；再保证任务隔离、容量预留、取消/抢占、结果验证及节点失败后的可恢复执行。

这不是“存在多种硬件”或“多个 worker 并行”就能推出的能力。资源登记、健康状态、能力匹配、调度决策、执行隔离与 durable side effect 的 fencing 必须构成产品合同；当前资料没有决定支持的设备类型、任务类型、资源 owner 或成本目标。

## 2. 当前证据与不可外推事项

- 分布式授权实验记录三台异构 CPU 主机参与授权集群测试，并区分同 JVM、单机多进程、三主机等拓扑；异构硬件用于实验/部署和性能分层观察，不是资源发现或工作负载路由服务。历史实验资产不是当前生产运行证明。详见 [分布式测试说明](../../实验/分布式测试/README.md) 与 [性能记录](../../实验/分布式测试/rust-s15/PERF_20260901.md)。
- `AuthorizationProjector` 的 `TenantSerial`/`Partitioned` 是授权投影事件在租户/聚合分区上的特定调度方式，围绕 durable ledger、aggregate lease 和 worker 预算工作；`TenantSerial` 是默认模式，`Partitioned` 需显式启用并受连接池预算约束，真实多 worker 集成和基准仍未完成。它不是接受任意 CPU/GPU/ARM 作业的产品 scheduler。
- 分布式测试 harness 的多节点、测试 worker 并行及 projector worker pool 分别服务于测试协调或授权投影生命周期，不意味着闲置设备登记、任务优先级、公平队列、通用工作负载执行或异构路由已实现。
- [能力清单](../../技术能力与储备清单.md) 将 CPU/GPU/ARM 可插拔裁决后端、统一设备抽象、CPU/GPU 智能路由、显存/内存分片和退役服务器复用列为无实现证据项。逻辑 HAMT/segment 与设备内存分片无关。

## 3. 候选架构与任务生命周期（未批准）

若该方向进入正式方案，可按以下职责拆分评审；没有选择具体 scheduler、agent、broker、container runtime 或 API：

1. **资源代理/登记**：每个受管理节点报告经认证的 node identity、硬件/软件 capabilities、容量、故障域、健康/心跳和可接任务标签；控制面校验声明，区分 capacity advertised 与可实际执行能力。节点离线或健康未知时应从可分配集合移除，而不是沿用旧容量。
2. **任务描述与 admission**：任务以稳定 `operationId`/task ID 描述资源需求、兼容 ABI/runtime、数据位置、租户/安全域、优先级、deadline、可否抢占、重试安全性和输出合同。admission 先检查配额、来源与制品完整性，再排队或明确拒绝，不能让任务携带绕过授权的可执行策略。
3. **匹配、预留与派发**：候选调度器按能力兼容、可用容量、数据 locality、优先级/公平性和故障域做 placement；用有过期时间的原子 reservation/lease 避免并发超分配，并对 node/lease generation 做 fencing。具体目标函数、抢占规则、公平算法和资源报价策略均待决策。
4. **隔离执行与结果提交**：执行端按租户/任务做资源、网络和文件隔离；通过受校验的 artifact 输入输出接口执行。完成结果须绑定任务/attempt 身份和内容完整性；有外部或 durable 副作用的任务必须将其纳入 stable operation ID、幂等或显式未知结果对账合同，不能只凭 worker ACK 接受。
5. **回收、重调度与审计**：任务完成/失败/取消后释放 reservation；节点失联时先 fence 旧 owner，再根据任务副作用类型决定安全重试、隔离或人工对账。记录排队、调度、运行、回收和成本/资源使用证据，避免陈旧 worker 在重调度后继续提交结果。

### 候选取舍

中心化调度便于统一配额、公平性和审计，但成为控制面热点/故障域；分布式调度扩展性较好，却需要更复杂的一致性、冲突仲裁和资源超卖控制。可抢占提高紧急任务可用性但要求任务可检查点/可重入；仅使用可重试任务较简单，但必须严格拒绝对未知外部结果盲目重放。硬件标签和“空闲率”容易漂移，实际性能/能耗需基于节点本地观测，不能跨异构硬件直接平均 P99。这里是评审维度，不是推荐产品选型。

## 4. 故障、数据与安全边界

资源发现不可用、节点健康过期、能力声明不可信、容量预留冲突、执行超时、取消竞态、节点崩溃、artifact 损坏和调度器重启都要有明确定义的状态及恢复 owner。缺乏可信容量/租户身份/任务来源时，安全默认是拒绝分派或保持待处理，不应把任务发往“看起来在线”的机器。租户间任务和数据需隔离，敏感制品应验证来源、访问权限及完整性；scheduler 的位置决策不是授权依据，任务实际调用仍受业务授权合同约束。

执行者租约到期不证明旧进程已停；重派前需要 token/generation fence，并在任何 durable/external side effect 前验证仍持有当前 owner。提交结果未知时先依据稳定 ID 和 durable receipt 对账；只有确认无副作用或幂等合同与 CAS/lease 保护成立才可重试。不能把通用 projector 的 lease/fence 机制直接宣称已满足 arbitrary workload 的生命周期要求。

## 5. 当前批准、实现与验收状态

- **产品目标/设计批准**：目前仅为能力清单规划储备；未发现经批准的异构资源注册协议、通用任务调度器、设备抽象或编排合同。
- **实现**：无产品级资源发现、闲置算力路由或任意工作负载编排的实现证据。异构 CPU 测试拓扑与授权 `AuthorizationProjector` partitioned worker 均是相邻但不同的能力。
- **验收**：有分布式授权实验及硬件分层的历史资料，不构成当前异构任务 scheduler 的性能、容量、安全或故障恢复验收。本文件未启动服务、容器、集群或基准，也不宣称运行态可用。

进入专项设计前需先确定目标工作负载/硬件范围、资源 owner 与可信身份、租户与数据边界、任务副作用类别、调度/隔离运行时、队列容量/公平规则、过载策略、失败重试合同、观测与成本限额及受保护验收环境。正式验收应覆盖节点过期、能力误报、资源争用、隔离逃逸边界、抢占/取消竞态、旧 owner 迟到提交、artifact 校验、集群分区、未知结果对账和真实异构负载；具体阈值由批准的专项设计定义。

**结论：**异构算力编排仍处概念/规划层。异构测试拓扑和特定授权 projector 的 partitioned worker 都不能证明产品级通用 scheduler 已存在。
