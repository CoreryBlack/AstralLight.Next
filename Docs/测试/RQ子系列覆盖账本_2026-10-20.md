## 1. 登记变更

本次在 `tests-suite/MANIFEST.toml` 增加：

- series：`RQ-A`、`RQ-B`、`RQ-Compare`、`RQ5-E`
- blocked suites：
  - `rq-a-rule-complexity`
  - `rq-b-card-scale`
  - `rq-compare-layers`
  - `rq5-toctou`
  - `rq5-stale-token-replay`
  - `rq5-throughput`

这些 suite 没有伪造 `argv` 或成功结果；它们只把外部依赖和缺口显式登记，避免被误认为已覆盖。

`bench/engine-comparison` 的梯度已按 Java `ScaleConfig` 的 **cross-system** 口径对齐：

- 默认 `--gradient=rq-compare-1`：100 / 1K / 10K / 50K 卡 × 40 base rules；
- `--gradient=rq-a`：10K 卡 × 10 / 50 / 100 / 500 / 1K base rules；
- `--gradient=rq-b`：100 / 1K / 10K / 50K 卡 × 40 base rules；
- `--gradient=native-rq-a`：10K 卡 × 10 / 50 / 100 / 500 / 1K / 5K base rules；
- `--gradient=native-rq-b`：100 / 1K / 10K / 50K / 100K / 400K / 500K / 1M 卡 × 45 nominal rules；
- `--gradient=local`：保留原有开发用小矩阵。

`native-*` 是 **base-only 近似**：未建模 overlay/ABAC/模板；Storage 是
`size_of<CanonicalGrant>() × cards × entries` 的估算，不是实际引擎/DB 存储。
单个 cell 超过 2M grants 时必须显式 `--allow-large-gradient`，因此 native
profile 的 5M/10M/45M cell 默认只可通过 `--list-gradients` 查看，不能直接运行。
Casbin(Cached)、OPA(cached)、OPA(no-cache) 已加入 engine list；SpiceDB 未加入，
因为 Java `BenchmarkRunner` 明确移除了 RQ-Compare-4（ReBAC 与 RBAC 不可比）。

## 3. 结论

- **RQ-A/RQ-B/RQ-Compare** 现在已进入 MANIFEST，但状态是 BLOCKED：缺少 CasbinCached、OPA cached、SpiceDB、精确梯度和存储/TPS 采集。
- **RQ5-E2/E3/E5/E11** 已有正式 suite 名称，但依赖已部署签名 HTTP/三节点环境，当前不能执行。
- **RQ2-A..K、RQ3/RQ4 子项** 仍主要是语义/组件覆盖，不能因为 RQ2/RQ3/RQ4 主标签存在就视为完整。
- 要得到完整 RQ 结论，必须补齐外部 comparator、保护部署和真实服务证据；在此之前，任何“RQ 全系列 PASS”的表述都不成立。
