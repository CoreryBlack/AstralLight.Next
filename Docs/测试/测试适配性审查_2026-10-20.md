> 日期：2026-10-20
> 范围：当前仓库 `AstralLight.Next` 的 Rust 测试、tests-suite、bench、归档 Java/继承资产
> 基线：当前 `main` 的测试布局与 MANIFEST

## 1. 结论

当前没有失败测试；默认原生 workspace 为 **2,774 passed / 0 failed / 104 ignored**。兼容/legacy 测试已从默认 gate 移出。

“不适配当前架构”的测试分为三类：

1. **已正确标记为 compat/archived/blocked 的测试**：保留，不应删除，但不得当作当前生产路径通过。
2. **原先混在 current 默认集的 legacy 测试**：已通过 feature 开关移出默认编译，作为显式 opt-in 兼容覆盖保留。
3. **历史归档/外部依赖测试**：保留源码，不进入默认 gate；不为了“全绿”删除或伪造。

没有发现默认路径中仍引用已删除测试目录、旧 `cargo test -p <crate> --test` 命令或不存在 fixture 的情况。

- `tests-suite/MANIFEST` 的 `inline/policy-engine` note 已记录默认 248 / opt-in 46 的口径。
- 这些测试仍保留，因为它们是 legacy/test repository 的兼容守卫；默认生产 strict 测试不依赖它们。

   这些是测试代码质量问题，不是兼容路径；需要逐项改写或提供有依据的局部 allow，不能全局关闭 lint。

2. **兼容测试仍需显式 opt-in**
   - PolicyEngine 46 个 legacy L1/L2/fallback/CARD_ONLY 测试：`--features legacy-tests`
   - Java/Rust oracle：`--features compat-oracle`

   默认原生 gate 已不运行；如果要求“源码中也完全不存在兼容测试”，则需要单独删除/迁移决策，当前是保留而非删除。

   - native HTTP、native live fault、E1 race、E3/E4 fault、E5 TLC

   这些不是测试代码未适配，而是缺少批准环境；不能用 mock 或历史结果替代。
