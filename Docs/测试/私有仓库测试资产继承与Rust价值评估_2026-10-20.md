## 5. 建议

1. **优先迁移 P0 场景，不复制 Java 代码**：把三节点投影、lease/fence、故障注入、
   卡切换、跨租户安全和属性测试映射为 Rust `tests-suite` 的 RQ3/RQ4/S15 场景。
2. **逐项处理 9 个 Rust 测试名差异**：`bypass` 已由 async scoped 测试替代；
   tenant/audit 测试已改为 `..._fails_closed`。剩余名称应补映射或明确记录为删除。
3. **P1 作为契约清单**：Learn 权限契约、Gateway 路径、Web API/permission 契约可直接
   转成 Rust HTTP/DTO 断言，不需要引入 Java/JS 运行环境。
4. **历史 S15 证据只作回溯**：不得用继承的 REPORT/JSON/归档声明当前 PASS；
   真实三节点仍需受保护环境、审批、fresh deployment 和新证据。
5. **更新私有仓库的测试清单文档**：357 与实际 791 不一致；若把它作为完整性基线，
   必须先按当前 HEAD 重新生成并记录 commit/hash。

## 6. 证据边界

- 本次没有运行私有 Java/Web/移动端测试，也没有启动三节点、MySQL、RabbitMQ 或 Redis。
- 当前仓库只验证了资产复制、地址脱敏、文件存在性和 Markdown 链接；S15 harness 未执行。
- 继承的历史结果不代表当前代码或部署；任何生产/安全结论仍需当前快照下的重新验证。
