## 当前生效的路径体系（截至 2026-09-09）

### Java Gateway 路由（`Gateway/src/main/resources/application.yml`）

| 路由族 | 路径 | 目标服务 | 说明 |
|--------|------|----------|------|
| Learn App | `/v1/app/**` | AstralLearn | 主路径 |
| Learn Admin | `/v1/admin/learn/**` | AstralLearn | 管理端主路径 |
| Learn 兼容 alias | `/api/v1/learn/**` | AstralLearn | 兼容 alias，不新增能力 |
| Chat | `/api/v1/chat/**`、`/ws/**` | AstralChat | 含 WebSocket |
| Identity | `/api/v1/auth/**`、`/api/v1/users/**` | AstralIdentity | 认证与会话 |
| TrustGraph 主入口 | `/main/**` | AstralTrustGraph | Controller 前缀 `/main`，冻结主入口 `/main/api/v1/**` |
| Monitor | `/api/v1/monitor/**`、`/api/health/**` | Monitor | 监控与健康 |
| Duo 兼容 | `/duo/v1/app/**`、`/duo/v1/admin/learn/**` | AstralLearn | `StripPrefix=1` 兼容路由；继续保留并定期评审 |
| 文档路由 | `/learn|/chat|/trust` 前缀 + `/v3/api-docs/**`、`/swagger-ui/**` | 各服务 | 仅 OpenAPI 文档路由，不构成业务前缀 |
| checkins 重写 | `/v1/app/users/checkins/**`、`/v1/app/users/*/checkins/**` | AstralLearn | `RewritePath` 到 learn checkins |

### Rust 网关（`astral-gateway`）

- `/api/v1/auth/**` 认证族：`/api/v1/auth/me/permissions`、`/api/v1/auth/me/cards`、`/api/v1/auth/sessions/*` 等为实际可用入口。
- `/v1/chat/**` 与 `/v1/chat/ws/{user_id}`：Chat 路由。

### 不存在的路径

以下路径没有 Controller 或 Gateway 路由，不得写成现行路径：

- `/identity/**`：外部身份路径不存在；Identity 对外走 `/api/v1/auth/**` 与 `/api/v1/users/**`。
- `/api/v1/migration/**`：数据迁移 API 为未实现的历史设计稿。
- `/authz/**`：无对应路由。
- `/api/v1/users/{id}/permissions`：历史示例性幻影路径；实际等价入口是 `/api/v1/auth/me/permissions`。

## 路径命名约定

```
[兼容前缀]/[api|main|v1/app|v1/admin]/[resource][/{id}][/{sub-resource}]
```

| 部分 | 示例 | 说明 |
|------|------|------|
| 兼容前缀 | `duo` | 仅既有兼容路由，不扩散 |
| 业务前缀 | `api`、`main`、`v1/app`、`v1/admin` | 各服务按冻结清单使用 |
| v1 | `v1` | API 版本号，当前统一为 v1 |
| resource | `users`, `subjects`, `permission-rules` | 资源名，小写复数，多词用横线 |
| id | `123` | 资源 ID |
| sub-resource | `permissions`, `cards`, `checkins` | 子资源或动作 |

`/main` 是 TrustGraph Controller 的 `@RequestMapping` 前缀，不是 `server.servlet.context-path`；TrustGraph 冻结主入口是 `/main/api/v1/**`，不得被泛化的"禁止 `/main/**`"规则误伤。

## 与 V4 规范的差异

| 项目 | V4（过时） | V5（现行） |
|------|-----------|-----------|
| 版本号 | `v4`（长期目标，从未实现） | `v1`（实际生效） |
| 路径结构 | `{domain}/{surface}/{resource}` | 冻结清单 + 兼容 alias 分层 |
| domain 维度 | `/api/v4/system/subject/` | 不存在于路径中 |
| 实现状态 | 规划阶段 | 以 Java Gateway 路由表、Controller 前缀和 Rust 网关路由为准；兼容 alias 继续保留并定期评审，不描述为"已全部下线" |

---

## 新增路径约定

1. 新增模块/Controller 继续使用 `v1` 版本号
2. 路径中的资源名使用小写复数 + 横线分隔（如 `permission-rules`）
3. 动作作为子路径，不放在版本号中；旧动作子路径（如 `rebuild-snapshot`）属于 Java 历史实现，不作为新路径模板
4. 不要引入 `v2`、`v3` 等新版本号——当前架构不需要 API 版本共存
