项目与愿景 PROJECT / VISION

让每一次授权，
都可证明、安全、轻量。

AstralLight 用 Rust 把 source 变更、证据发布、准入判断、host 执行与审计对账组织成一条可检查、可恢复的链路。它不是新的策略语言，而是补齐策略引擎与真实执行之间的证据准入层。

可证明的链路每个决定都能回到发布证据与被准入的 grant。
足够安全的访问不确定时返回 PENDING 或 DENY，不回退旧 ALLOW。
尽可能低的消耗增量编译、有界缓存、按需读取，减少多余成本。

01 失效场景

一次 stale ALLOW，如何穿过所有局部正确的检查？

设请求上下文为 ctx = (principal, tenant, scope, resource, action)。候选授权 g₀ 仍在证据集 E₀ 中；source 事务提交了一个收窄变更 d，把 g₀ 从有效授权中移除。

投影尚未发布 d，缓存仍持有 E₀。策略匹配器对 E₀ 执行匹配，正确选中 g₀；host 随后执行受保护操作。source 提交正确，投影按自己的进度工作，缓存记录完整且签名有效，匹配器也没有算错——但系统最终执行了错误的状态。

这不是一句“缓存没刷新”能概括的问题。即使缓存完全新鲜、完整性校验通过、策略语言语义正确，只要派生证据还没有表示某项已提交的撤权，匹配结果就可能是一份过期的候选。

  1. tc(d)

    source 事务提交收窄 d，并在同一短事务中留下 durable delta 或 outbox、source generation、revoke fence、受影响 scope 与审计关联。

  2. m0 → p0 → m1 → p1

    若命中缓存，读取端按顺序观察 manifest 摘要 M 与未发布收窄谓词 b；这四个语句不是同一个原子 SQL 快照。

  3. tf = t*

    最终加载的第一次权威观察。缓存分支取 m0；严格读取分支取首次谓词读视图。它提供用于准入的最终证据 E1。

  4. tv → ta

    身份稳定检查完成于 tv，ALLOW 返回 host 于 ta。保证只覆盖 tc(d) < t* 的撤权类变更；落在 [t*, ta] 内的变化不在定理范围内。

关键不在“缓存了多久”。只要证据还没有表示已提交的收窄，host 就可能把一次正确的局部匹配，执行成一次错误的全局决定。

02 边界问题

策略引擎回答的是“是否匹配”，不是“这份状态是否仍可执行”。

RBAC 从角色派生权限，ABAC 组合主体、资源、动作与环境属性，XACML 定义组合与 Indeterminate 结果，Zanzibar 暴露关系元组的 consistency token；Cedar、OPA、Casbin 等进程内或 sidecar 引擎，则评估调用方提供的策略与实体表示。

这些系统定义了“给定输入状态，如何得到一个决定”。它们没有、也不应该单独负责证明三件事：

  • 输入状态是否包含了所有相关的 source 侧收窄。
  • 正在被使用的派生表示，是否就是发布链上那个可验证的表示。
  • 同一资源与动作上的重新授权，是否仍然是原来的那一个 grant。

论文把这一问题概括为从 candidate entitlement 到 executable authority 的 evidence admission（证据准入）。它不替代策略语言，也不声称解决任意策略语义的一致性；它只处理一个系统安全问题：一个候选匹配，什么时候可以跨越 host 边界，变成可执行授权。

这类似分布式系统里的 check–use gap：source 侧检查、派生表示和 host 使用可以观察到不同状态。Lease、sequencer、consistency token、概率陈旧度、CRL/OCSP 和 OAuth device pending 都提供了有价值的局部构件，但它们没有自动把 freshness 绑定到具体 grant 与宿主效果上。

问题不在策略表达力，而在输入状态的来源、表示与身份。把这一层省略掉，再正确的匹配器也只能对一个可能过期的世界负责。

03 候选与授权

候选资格是匹配结果，可执行授权是安全决定。

论文用四个通用对象描述问题：principal 在 tenant 与 authorization scope 内，对某个 resource 请求一个 action；grant 带有 origin、tenant、principal、scope、resource、action、有效期、provenance、逻辑标识与 revision；candidate entitlement 是请求对给定证据集 E 的确定性匹配；executable authority 是候选通过最终准入后的结果。请求上下文 ctx 绑定 principal、scope、tenant、resource 与 action，证据集 E 则包含准入 gate、有序 manifest 摘要、发布 watermark、完整性元数据与有效 grant 集合。

CANDIDATE ENTITLEMENT

候选资格

在给定证据集 E 上，按固定顺序执行一次确定性匹配，选出的第一个在 scope 内、时间有效且结果为 ALLOW 的 grant。

它只说明：在这份证据上，这个请求“匹配得上”。

EXECUTABLE AUTHORITY

可执行授权

候选只有在最终准入验证了 source-linked evidence、scope、publication identity，以及最终重载时的 exact candidate identity 之后，才成为可执行授权。

它说明的是：host 现在可以安全地执行受保护操作。

这两者之间不是“再查一次缓存”的差别，而是一份显式的 admission contract。候选可以来自内存、缓存或严格读取；只有通过最终准入的候选，才允许跨过 host 边界。

核心区分

策略系统可以正确回答 match(ctx, E)；证据准入还要回答：E 是否遗漏了本 scope 已提交的收窄，E 是否是可验证的发布表示，以及最终被准入的是否仍是候选 g₀ 本身。

04 五个连接

把 source 变更，接到 host 的那一次授权决定上。

论文的准入合同由五个连接组成。它们不一定分别新颖，也不声称是最小机制集合；安全价值来自它们被接成一条可检查的链。

  1. 01

    来源事务

    source mutation 在短事务内持久记录 durable delta 或 outbox、source generation、revoke fence、tenant 与所有受影响 scope。网络调用、缓存推送、投影和重试都不在事务内。

  2. 02

    发布围栏

    generation 与 revoke fence 单调推进，旧的 owner 不能在更新的 generation 之后完成发布。成功发布由 committed manifest/segment/current pointer 证明，而不是 ACK 或 best-effort cache push。

  3. 03

    收窄遗漏探测

    在信任缓存候选之前，保守检查本 scope 是否存在“可见、但尚未成功发布到当前 watermark”的收窄。零结果只表示没有已知阻塞收窄，不表示全局策略已经收敛。

  4. 04

    读取观察合同

    缓存候选必须通过两次有序权威观察并保持相等，或者由 strict reader 取得一个新鲜的 committed-state 读视图。候选自己的摘要还必须与观察到的发布身份一致。

  5. 05

    最终身份重载

    host 返回前再次加载证据，并绑定相同 scope、发布证据、logical id、revision、origin 与 provenance。只匹配 resource/action 不足以证明还是同一个 grant。

任何一条断开，局部检查都可能仍然显示正常。这正是下一节要展开的“局部正确”：每个组件都能通过自己的接口，但系统整体已经不再表示 source 的最新收窄。

05 局部正确

只保留一个局部检查，仍然可能放行旧授权。

论文用六种分析性遗漏调度说明：移除一个连接、保留其余局部检查时，系统仍可能看起来健康，却遗漏了本应阻断的收窄。它们是设计推理，不是已经完成的消融实验结果。

保留 published generation

d 在发布等待期间提交；缓存的 grant 与 pointer 仍是旧 generation，单看 generation 也自洽。

必须补上：source-visible 未发布收窄探测。

保留 cache token

d 已提交，但 token 未轮换；一条认证通过的缓存记录仍带着当前 token。

必须补上：token equality 是 lineage，不是 source freshness。

保留 publication watermark

新的 pointer 已被观察到，但 host 使用了 g₀，没有把 payload 与 scope 绑定到已校验的证据链。

必须补上：evidence representation 与 identity validation。

只做一次 manifest–predicate pass

d 在 M 与 b 两条语句之间提交，这一对观察组合了两个不同的 committed states。

必须补上：两次有序观察并要求 Qpre = Qpost。

保留 projection reload

两次加载在内部都有效，但已提交的 d 仍然没有被发布到当前 watermark。

必须补上：最终加载也执行 source-linked probe。

保留 resource/action rematch

撤权后重新授权，resource 与 action 相同，但 successor 获得了新的 revision 或不同的 provenance。

必须补上：绑定 origin、logical id、revision、payload 与 publication identity。

这些调度不是“攻击已经复现”的证据。它们说明的是组成关系：局部检查之间的空隙，恰好是 stale authority 可以穿过的位置；受控遗漏实验仍属于计划中的评测 gate。

06 对手与目标

受保护的是准入边界上的决定完整性。

受保护资产不是“策略文件不被修改”，而是 host admission boundary 上的 decision integrity：一个请求不能基于遗漏了可见、相关收窄的证据，被当成 ALLOW 执行。

主要对手是一个已认证的请求方：它可以重放仍在有效期内的签名请求、切换目标，或把一次 source mutation 与一次授权决定赛跑。它不需要直接控制可信存储，只需要利用正常的异步行为——投影延迟、缓存残留、worker 调度、lease 过期和基础设施故障。

系统同时保护 tenant 与 scope 的隔离、候选的 provenance，以及用于证明决定的发布证据的单调性。信任前提是：Gateway 完成外部认证并签名身份上下文；权威存储、读取端、projector 与完整性密钥不是 Byzantine；每个被评估的 aggregate 只有一个 source writer；所有受保护操作都经过完整的 host mediation。

五个安全目标

  1. G1

    Revocation admission

    候选只有在最终权威观察之前、所有相关撤权类变更都已经成功发布并被最终证据表示时，才成为可执行授权；未发布收窄只能得到 PENDING 或 DENY。

  2. G2

    Publication ownership

    source generation、revoke fence 与发布 pointer 单调推进；陈旧 worker 不能完成新 owner 的发布，durable event 只有一个终态转换。

  3. G3

    Scope isolation

    匹配与准入始终绑定请求的 principal、tenant、scope、resource 与 action；重放或上下文切换不能扩大这些字段。

  4. G4

    Evidence identity

    被准入的证据必须标识候选的 origin、logical id、revision、provenance、有序 manifest 链与完整性元数据；同 resource/action 的 successor 不能替代原候选。

  5. G5

    Fail-closed uncertainty

    缺失、变化中、格式错误、不可用或无法验证的证据不能产生 ALLOW；PENDING 是显式的非准入结果，不是重试或可用性承诺。

不覆盖的范围同样是问题定义的一部分：Byzantine 进程、直接入侵 MySQL/RabbitMQ、in-process hub 被攻破、主动拦截可信节点流量、恶意或多个 writer、replica 分歧、密钥被攻破、无界 clock skew，以及后续业务效果的原子性。定理是 grant-specific 的准入合同，不是“任意攻击者下全面安全”的声明。

07 来源与发布

先让变更成为可发布的事实，再让发布成为可验证的事实。

短事务只记录来源事实

source mutation 与 durable delta/outbox、source generation、revoke fence、tenant、全部受影响 scope 以及审计关联一起提交。事务边界保持很短：网络调用、缓存推送、投影工作、重试和验证都不放进去。

围栏发布只承认 committed evidence

受监督的 projector 用 compare-and-set lease 与 generation fence 认领 delta，只应用已批准的 mutation，校验结果的不可变 segment，然后把 pointer 推进到一份已提交的 manifest。manifest 的有序摘要携带成功 watermark。较旧的 owner 不能在新 generation 胜出后完成发布；未知的 worker 结果必须先对账，再决定是否重试。

表示是 content-addressed 且 scope-aware 的：manifest 摘要写明 aggregate、generation、revoke fence 与 segment 链；effective grant 带有 logical id、revision、scope、有效期和 provenance。持久 HAMT 的结构性共享减少无关重建，但它是性能优化，从属于证据身份——一个未变化的共享 segment 不能掩盖变化的 card binding 或 fence。

ACK 不是 publication proof。broker confirm、cache push、队列接收或 handler 完成，都不能单独证明授权状态已经成功发布。

08 遗漏探测

只阻挡未发布的收窄，不阻挡正常的新增。

这里的 narrowing（收窄） 指移除、撤销、被保守标记为 invalidating 的授权内容更新，或携带更高 revoke fence 的变更。真正的 aggregate-wide mutation 会为每个受影响 scope 表示；共享 rule-set 的移除会展开为逐 scope 贡献。

在信任一个缓存候选之前，读取端提出一个保守问题：

THE NARROWING PROBE

本 scope 是否存在任何可见、但尚未成功发布到当前 watermark 的收窄变更？

谓词包含 pending、invalid、quarantined 或 fence-leading 的 delta。零结果不表示“所有可能的策略变化都已在全局收敛”，它只表示：在本 scope 的 source/publication contract 下，没有已知的阻塞性收窄。

这种不对称是刻意设计的。若一个新增尚未进入证据，直接后果是新权限被延迟；若一个收窄尚未进入证据，已经匹配的 grant 会在 source 撤回后继续可执行。前者可以等待常规发布，后者必须阻断。这是安全选择，不是“其他 card 完全不受影响”的声明。

不是所有延迟都等价。ADD 的延迟影响可用性；NARROWING 的延迟影响授权正确性。准入合同只对后者施加额外的阻断条件。

09 读取路径

缓存分支要求两次有序观察，严格分支要求新鲜读视图。

缓存候选

一个缓存候选包含 tenant 与 scope、evidence gate、有序 manifest 摘要、generation 与 revoke fence、内容 hash、完整性 tag、cache-generation token、有效期以及完整的 effective grant 集合。L1 缓存有容量与时间边界；L2 记录经过认证并会过期。缓存失败、tag 无效、epoch 不匹配或 validity window 变化，都会把请求送到 strict reader。

两次有序观察

缓存读取端执行两次权威观察，每次由独立的 pool-level autocommit 语句组成：

  1. m0 读取有序 manifest 摘要 M0，p0 读取未发布收窄谓词 b0。
  2. 再次读取 m1 与 p1，要求观察顺序 m0 → p0 → m1 → p1。
  3. 候选必须满足 Qpre = Qpost 且 b0 = b1 = 0，并且自身摘要与观察到的 publication identity 一致。

这四个语句不是一个原子 SQL 快照。一个 mutation 可能在 m1 之后、p1 之前提交，而不改变已采样的 M 值。因此定理只覆盖在第一次权威观察 m0 之前提交的收窄，而不是 p1 之前的每一个事件。

严格读取

strict reader 启动一个新事务，把 narrowing predicate 作为第一次一致性读；随后取得当前 pointer 与 manifest，校验 scope、segment 顺序与 hash 链，拒绝不一致或陈旧的链。证明依赖这个新鲜的 committed-state read view，而不依赖一份没有被冻结实验归档过的隔离级别声明。

缓存命中不是授权事实。TTL、token 和 hit 只描述驻留与谱系；source freshness 必须由 source-linked observation 证明。

10 最终重载

匹配出的 g₀ 不是授权，最终重载必须再次证明它是同一个 grant。

对 E0 的匹配产生候选，而不是 authority。决定路径会重复加载证据，得到 E1，并验证它与请求的 tenant、scope、gate、有序 manifest 摘要、generation、fence、完整性元数据以及 exact canonical grant 一致。

exact check 不只是 resource 与 action：它还包括 grant 的 origin、logical id、revision 与 provenance。一个逻辑标识可能在 tombstone 之后被重新使用，但 revision 不会被重新分配给另一条记录。

为什么 resource/action 不够

撤权后重新授权可能产生相同的 resource 与 action，却是一个 successor revision。若只按 resource/action 重新匹配，旧候选会被这个 successor “接上”，看起来仍然合法；但 origin、revision 或 provenance 已经不是原来那个 grant。最终重载必须让这种替换失败。

host fence

host 在资源归属与评估之前捕获一个 opaque authority fence，在辅助权威读取之后、进入下游 handler 之前比较原 fence。一个使原 fence 失效的 cold refill 不能被静默替换为请求的新基线；该请求必须被拒绝，后续请求重新评估。这是 admission mediation，不是 handler 后续业务效果的原子化。

最终重载不是“再查一次”。它要同时证明发布身份、scope 与候选身份没有在决定过程中漂移。

11 失败语义

失败时只有两种安全结果：PENDING 或 DENY。

唯一的成功结果是：通过 stable check 后返回 ALLOW。无匹配或无效上下文返回 DEFAULT_DENY；证据未就绪、变化中、缺失、格式错误或无法验证时，按失败类别返回 AUTHORIZATION_PENDING 或 DEFAULT_DENY。

  • 没有匹配或上下文无效：DEFAULT_DENY。
  • 证据缺失、陈旧、变化中或无法验证：PENDING 或 DENY，绝不回退到旧的 ALLOW。
  • PENDING 不能被缓存为授权，不能被当作后续请求的放行依据，也不能复用之前的 ALLOW。
  • 当前 API 不承诺统一的 retry interval；调用方需要应用自己的有界策略。
  • 业务 PENDING 不会推进基础设施 circuit breaker。

当前兼容入口把 DENY 与 PENDING 都映射为 HTTP 403，并保留语义 reason code；集成映射或策略拒绝使用 403，身份/会话失败使用 401，pending 或不可用证据可以使用 503。传输状态本身不能替代语义决定，实验必须记录实际 decision 与 host outcome。

PENDING 不是“稍后会自动放行”。它明确表示证据不足，受保护效果不得执行；可用性代价是这份合同的一部分。

12 请求生命周期

匹配很快，时间花在往返上。

一次签名请求要穿过连接、身份、证据读取、匹配和最终重载。把各阶段与现有基准对齐，瓶颈很明确：编译匹配只占极小部分，主要成本在网络、身份/会话和证据 I/O。

  1. 01

    入口与 HTTP

    连接接纳、HTTP 解析、签名头校验；跨进程请求在这里产生第一段网络与排队成本。

    NETWORK
  2. 02

    身份与上下文

    JWT / session、双卡绑定、tenant、scope 与 principal 校验；需要会话或身份映射读取。

    CPU + I/O
  3. 03

    候选证据加载

    内存 hub 命中，或 strict refill 读取 current pointer、manifest、segment 与 pending predicate。

    I/O / CACHE
  4. 04

    编译匹配

    编译内核在稳定 grant 集上选出候选；这就是 0.10–0.47µs 微基准所测的部分。

    CPU
  5. 05

    最终重载与 host fence

    再次加载证据、复核 exact grant 与发布身份；辅助读取与 fence 比较仍在 I/O 路径上。

    I/O
  6. 06

    响应与提交后处理

    序列化、HTTP 返回，以及提交后的审计/outbox；审计异步化时不一定在请求关键路径上。

    NETWORK / I/O

13 条件保证

一个带前提、针对具体 grant 的条件安全保证。

在上述来源、发布、存储完整性、读取观察与 host mediation 前提下，论文给出一个条件定理。它不是对所有策略变化的全局快照，也不是对部署的机器化证明。

五个前提

  • M1 来源捕获：每个相关的 source mutation 原子地记录 durable delta/outbox、source generation、revoke fence、tenant 与全部受影响 scope；收窄分类采取保守策略。
  • M2 单调发布：成功发布原子地记录严格推进的 affected-scope watermark 与 pointer；摘要不会回滚，也不会被复用于另一个状态。
  • M3 忠实表示：projector 只把已批准的 delta 物化为有序、带完整性校验的证据；一个已被发布覆盖的贡献，必须持续被其 watermark 所表示。
  • M4 可信存储与进程：权威 writer、读取端、projector 与完整性密钥不是 Byzantine；不匹配、缺失记录与未知结果都 fail closed。
  • M5 完整中介：每一个受保护的 host 操作都以绑定的 context 调用 evaluator，并且只有 ALLOW 之后才继续执行。

除 M1–M5 外，读取端的两条观察合同与 grant revision ledger 也是前提：前者见第 09 节，后者见第 10 节。

CONDITIONAL ADMISSION-SAFETY

在 M1–M5、读取观察合同与 grant revision ledger 合同下，每一次成功的 ALLOW 都存在一个一致性点 t* = tf：所有在 tf 之前提交、且对请求 scope 可见的撤权类变更，都已成功发布并被最终证据 E1 表示；E1 还必须绑定被准入的确切 candidate grant。无法建立该条件时，结果只能是 PENDING 或 DENY。

一致性点在哪里

tf 是提供成功最终证据的第一次权威观察：缓存分支取 m0，严格读取分支取初始谓词读视图。身份稳定检查完成于 tv，ALLOW 返回 host 于 ta，所以 tf ≤ tv ≤ ta。

四个支撑引理

  • 可见性捕获：在一次新鲜谓词读之前提交的可见收窄，要么让 b = 1，要么已经成功发布。
  • 缓存观察与表示：通过两次有序观察与相等测试的缓存候选，表示 m0 之前提交的每一个可见撤权类变更。
  • 严格观察与表示：成功的严格加载表示其初始谓词读视图之前提交的每一个可见撤权类变更。
  • 候选身份绑定：不同的 grant revision 不能在满足 stable check 的同时替代原候选。

定理不覆盖什么

  • [tf, ta] 之间提交的重叠 mutation。
  • 后续业务效果本身的原子性；它需要 host 事务或 effect fence。
  • ADD 的可见性、Byzantine 存储、多 writer 排序与 replica 分歧。
  • 无界 clock skew、全局策略线性化，以及更丰富策略语言的组合语义。

这是一个充分的条件合同。它连接“可见的 pre-observation 撤权”与“被准入的确切 grant”，同时把可用性代价和未覆盖范围写在结果旁边。

14 证据分级

旧基线、当前测试与未闭合 gate，是三件不同的事。

论文刻意把证据分成三个 surface。把一个 surface 的 PASS 转移成另一个 surface 的结果，会让“问题定义”看起来比实际更完整。

BASELINE

冻结的三进程历史基线

三个 TrustGraph 进程共享 MySQL、Redis 与 RabbitMQ；11/11 计划步骤 PASS，270 PASS、0 FAIL、3 N/A。诊断 race 记录 30 cycles、12 readers、37,413 samples，0 个 post-ack stale 或 in-flight ALLOW、669 个 PENDING；传播均值约 572.6ms，撤权均值约 585.2ms。

只支持该部署与被实际执行的路径。诊断 race 不包含 production final identity-stable reload；它不是 native composite 的结果。

REGISTERED

当前 native 实现与测试

覆盖 compiler/policy/hub 的离线测试、MySQL-backed native lifecycle、standalone MySQL/RabbitMQ transport，以及 hub、writer-lock、identity-mapping、Redis-free 等前提 suite。

注册测试不等于完成的 campaign，也不能从组件或单机结果推断 signed HTTP host race 已通过。

PLANNED / BLOCKED

尚未闭合的评测 gate

E1 complete host race、E2 controlled omissions、E3 recovery/availability、E4 native preconditions/faults，以及 memory-served native admission 与定理之间缺失的映射，仍是独立 gate。

未见完整 artifact、时间点与 postcondition 前，不写成 PASS。ACK、cache hit、模型论证和“没有观察到失败”都不能替代这些证据。

证据状态不是 prose confidence。PLANNED 不能进入结果；UNKNOWN 不能转写成 PASS；旧 Redis/三进程基线不能冒充新 native composite 的测量。
